# 나중 아이디어: 등록 덱 비동기 래더 (기록만, 지금 만들지 않음)

2026-11-17 · 프런트컵 기획 결정(권장안 A) 5번 · 관련: `ladder-m2-plan-2026-11-16.md`, `cup-kit-host-guide.md`

프런트컵은 주최자가 한 번 모아 한 번 돌리는 행사입니다. 다음 단계로, 주최자 없이 늘 열려 있는 래더를 생각해 둡니다.

## 흐름

1. **덱 등록**: 유저가 지금 1군(프런트컵 엔트리 형식 그대로, `src/core/cup.mjs`)을 서버에 등록합니다. 저장(세계 id)마다 1개, 바꾸면 새 판으로 등록.
2. **도전**: 아무 유저나 등록된 덱 목록에서 상대를 골라(또는 비슷한 점수끼리 자동 짝) **자기 기기에서** 경기를 돌립니다. 엔진은 `cupMatch` 그대로, 시드는 (래더 id · 두 덱 해시 · 도전 번호).
3. **결과 보고**: 기기는 점수와 결과 해시만 서버에 보냅니다. 같은 입력이면 같은 결과라서 서버(또는 다른 기기)가 다시 돌려 맞는지 확인할 수 있습니다.
4. **순위 변동**: 확인된 결과로 덱 점수(Elo/Glicko)가 바뀌고 래더 순위표가 갱신됩니다.

## 지켜야 할 점

- 결과 위조: 보고된 해시 중 일부(또는 순위가 크게 바뀌는 결과)를 서버가 다시 돌려 대조합니다. 다르면 무효.
- 같은 상대를 반복해서 고르는 점수 올리기: 같은 짝은 하루 몇 번까지, 점수 변동은 상대 점수 차에 따라 줄입니다.
- 브라우저마다 다른 결과: 단장 대전 계획 1.5단계(사파리·파이어폭스 비교)를 먼저 끝냅니다.
- 덱 보관: 엔트리 25~35KB(사진 포함). KV 또는 D1. 오래 안 쓰는 덱은 내립니다.
- 보상: 칭호·배지만. 본게임 전력 보상은 주지 않습니다.

## 프런트컵과 같이 쓰는 것

엔트리 형식·해시·검증·금칙어, 경기 엔진(`cupMatch`), 경기 다시 보기 번호, 명예의 전당 화면.
