# UI/UX 검수와 개선 계획 (2026-11-15)

요청: "너무 버튼 UI가 버튼만 많고 별로인데 전체적으로 검수해서 개선점 기획해."
범위: 이 문서는 계획만 다룹니다. 코드는 바꾸지 않았습니다.

## 0. 측정 방법과 자료

- 빌드: `claude/kind-albattani-6wb1vz` 최신 커밋을 `bash build.sh`로 빌드한 `index.html`입니다.
- 상태 두 가지를 Playwright(Chromium)로 열었습니다.
  - 시즌 중: 6구단으로 창단하고 창단 드래프트를 마친 뒤 2026년 6월 20일까지 진행했습니다(37-35-1, 5위, 확인할 소식 6건).
  - 비시즌: 같은 방식으로 2026년 11월 6일까지 진행했습니다(스토브리그, FA 시장 협상 1일째).
- 화면 크기는 휴대폰 390×844와 PC 1366×768이며, 둘 다 deviceScaleFactor 1입니다. 메인 화면 8개, 하위 탭 50개, 선수 시트 7개 탭, 전체 메뉴를 찍었습니다. 스크린샷 134장은 저장소에 넣지 않고 작업 폴더 `scratchpad/uiaudit/`에만 두었습니다. 파일 이름 규칙은 `{mid|off}-{390|1366}-{화면}.png`입니다.
- 화면마다 DOM에서 아래 값을 셌습니다.
  - 조작 요소: `button`, `[data-a]`, `select`, `input`, `summary` 가운데 보이는 것입니다. 안쪽에 겹친 요소는 한 번만 셉니다.
  - 고정 셸: 모바일 상단 바와 하단 탭 13개, PC 상단 바와 사이드바 38개는 따로 셌습니다. 아래 표의 수치는 본문만 센 값입니다.
  - 첫 화면: 스크롤하지 않고 보이는 영역입니다.
  - 버튼 스타일 수: 배경, 테두리, 모서리, 글자 크기, 높이 조합이 다른 버튼의 수입니다.
  - 작은 터치 영역: 높이나 너비가 36px 미만인 요소입니다.
  - 도움말 아이콘: `data-a="help"`인 `?`와 `i` 버튼입니다.
  - 행당 버튼: 한 줄이나 카드 안에 든 버튼의 최대 개수입니다.
- 탭 수는 코드에서 확인했습니다. `src/ui/shell/03_menu.js`의 `NAV`/`SUBS`/`MERGE`와 `inTabs()` 호출을 기준으로 했습니다.

| 2 | **줄과 카드마다 강조 버튼이 붙어 있습니다.** 한 화면에 파란 버튼이 4~10개 보여서 지금 무엇을 해야 하는지 알 수 없습니다. | 트레이드 선수 찾기는 모든 줄에 파란 `협상 시작` 버튼이 있습니다. 휴대폰 첫 화면에 4개, PC에 7개입니다(`mid-390-trade-market.png`, `mid-1366-trade-market.png`). | 3 | **선수 시트 위쪽에 부가 동작이 몰려 있습니다.** 한 사람에 대한 동작 6개가 탭보다 위에 버튼으로 펼쳐져 있어 정보가 아래로 밀립니다. | 휴대폰 선수 시트 첫 화면에는 조작 요소가 25개 있습니다. `면담`, `시장 가치`, `트레이드 협상에 넣기`, `매물 목록에 올리기`, `트레이드 불가로 지정`, `연장 협상`에 `고치기`, `사진`, `이전/다음/뒤로`, 기간 칩 4개가 더해집니다. 결국 능력치는 첫 화면 아래쪽 1/3에서야 시작합니다(`mid-390-player-abil.png`). PC에서도 상단 줄에 같은 버튼 6개가 있습니다(`mid-1366-player-abil.png`). |
| 4 | **같은 이동 경로와 같은 정보가 여러 곳에 반복됩니다.** | PC 사이드바 메뉴 16개(스카우트, 스태프, 훈련·육성, 의료, 데이터 분석, 시설 …)와 상단 하위 탭 묶음(스태프·육성 = 감독/코치진/훈련·육성/스카우트/전력분석/분석원 관리/스태프 시장/부상 관리)은 서로 다르게 묶여 있습니다. 같은 화면으로 가는 길이 2개씩 있습니다. 진행 버튼은 `중계`, `하루 진행`, `진행하기`, `길게`로 상단에 3~4개가 있습니다(`off-1366-transfer-fa.png`). 소식함 PC 화면에서는 "확인할 소식"이 탭 숫자, 상단 링크, 오른쪽 패널, 목록 강조로 4번 반복됩니다. "분류별 안 읽음" 패널은 탭 숫자와 같은 내용입니다(`mid-1366-inbox.png`). 휴대폰에서는 소식함이 상단 아이콘과 하단 탭에 모두 있습니다. |
| 5 | **버튼 크기, 라벨, 도움말 아이콘이 제각각입니다.** | 휴대폰 화면 하나에 버튼 스타일이 평균 8.0개, PC는 15.9개입니다. 36px보다 작은 터치 영역이 화면당 평균 11.3개이고, 공통 컨트롤 높이 토큰부터 `--ui-control:32px`입니다. 휴대폰 50개 화면 가운데 49개에 `?/i` 도움말이 있고 모두 118개입니다. 설정 화면에만 12개, 시설 투자에 8개가 있습니다. 같은 "협상 열기" 동작의 라벨이 `협상 시작`, `협상`, `협상하기`, `협상실 열기`, `협상 테이블 열기`, `트레이드 협상에 넣기`로 6가지입니다. 채용도 `채용`, `후보 보기`, `채용 후보`, `스카우트 채용 → 스태프 시장`, `2년 계약`으로 나뉩니다. PC 계약 표의 `연장 협상` 버튼과 FA 표의 `협상` 열은 표 오른쪽에서 잘립니다(`mid-1366-transfer-contract.png`, `off-1366-transfer-fa.png`). FA 화면 안내문은 "표에서 협상을 누르면"이라고 하지만, 그 버튼은 보이지 않습니다. |

잘된 점도 있습니다. 이 패턴은 그대로 두고 다른 화면으로 넓혀야 합니다.

- 트레이드 `협상하기`(단장 카드를 누르면 열림)는 휴대폰 첫 화면 조작 요소가 11개로 가장 깔끔합니다.
- 소식함 휴대폰 화면은 줄을 누르면 열리는 목록입니다.
- PC 홈은 FM처럼 패널마다 오른쪽 위에 보조 링크가 하나씩만 있습니다.
- 선수 이름을 누르면 시트가 열리는 동작은 어느 화면에서나 같습니다.

## 3. 화면을 복잡하게 만드는 패턴과 FM/OOTP 비교

### 3.1 반복해서 보이는 패턴

1. **줄마다 동작 버튼이 있습니다.** 해당 화면은 트레이드 선수 찾기, FA, 무적 선수, 드래프트 `관심`, 계약 `연장 협상`, 시설 결제, 분석원 역할입니다. 정작 줄 자체(이름)를 누르면 선수 시트가 열리므로, 같은 줄에 누를 곳이 두 군데 생깁니다.
2. **필터 칩, 정렬 칩, 탭, 세그먼트가 위로 쌓입니다.** 선수단, 드래프트, FA, 트레이드 검색이 해당합니다. 필터를 접는 `▶ 필터·표시 설정` `details`가 있는 화면도 있지만, 칩이 접힌 영역 밖에 남아 있습니다.
3. **안쪽 탭이 계속 늘어납니다.** `MERGE`로 예전 화면들을 합치면서 합친 화면마다 `inTabs()`를 다시 썼습니다. `inTabs` 호출은 28곳입니다(정의 제외). 결과적으로 "탭 안의 탭"이 표준처럼 굳었습니다.
4. **이동 경로가 이중입니다.** PC 사이드바(16개)와 상단 하위 탭(`SUBS`)의 묶음이 다릅니다. 휴대폰 전체 메뉴는 하위 탭을 칩으로 다시 보여 줍니다. 홈 카드의 `전체/기록/선수단/재정` 링크도 같은 곳으로 갑니다.
5. **도움말 아이콘이 흩어져 있습니다.** 상단 `?`(설명 보기 전체 토글)와 패널마다 붙은 `i`가 따로 있습니다. `i`는 패널 제목, 지표, 보고서 문장마다 있습니다(선수 시트 보고서에만 4개).
6. **버튼 체계가 없습니다.** 실제로 쓰이는 클래스는 `btn`, `btn small`(374회), `btn small primary`(70), `btn primary`(54), `tc-i go`, `mt-go`, `chips button`, `seg button`, `pill` 버튼형입니다. CSS 쪽은 `!important`가 28개 파일에 301회 쓰였습니다. 모바일 분기점도 600, 699, 700, 1000, 1100px로 섞여 있습니다. `12_ux_fixes.css`(789줄), `40_mobile_playtest2.css` 같은 덧댄 층이 쌓인 상태입니다.
7. **공통 부품이 엉뚱한 파일에 있습니다.** `inTabs()`, `helpOn()`, `markHints()`가 `src/ui/market/23_trade_compare.js`에 있고, `optRow()`는 `src/ui/actions/41_guard_boot.js`에 있습니다. 공통 컴포넌트를 바꾸려 해도 찾기 어렵습니다.

### 3.2 FM/OOTP는 같은 문제를 어떻게 풀었나 (개념만 정리)

- **줄을 누르면 상세가 열리고, 동작은 상세 안에 있습니다.** 목록에는 정보만 있고, 동작은 선수 화면이나 오른쪽 클릭 메뉴에서 합니다. 목록 줄에 버튼을 두지 않습니다.
- **맥락 메뉴(`⋯`, 오른쪽 클릭)를 씁니다.** 선수 한 명에 대한 동작 수십 개(이적 제의, 임대, 계약, 매물 지정, 비교 …)가 메뉴 하나에 들어 있습니다. 화면에는 대표 동작 1~2개만 보입니다.
- **필터는 패널 하나에 모읍니다.** "필터" 버튼 하나를 누르면 패널이 열리고, 적용된 조건은 요약 칩 한 줄로 보여 줍니다. 정렬은 열 머리를 눌러서 합니다.
- **진행 버튼은 하나입니다.** 오른쪽 위 "계속(Continue)" 하나가 상황에 따라 라벨을 바꿉니다. 처리할 일이 있으면 그 일로 보냅니다. "~까지 진행" 같은 옵션은 버튼 옆 펼침 메뉴에 둡니다.
- **탭은 최대 2단계입니다.** 왼쪽 메뉴에서 화면을 고르고, 화면 위 탭 한 줄로 끝납니다. 세부 보기는 같은 화면 안의 "보기(View)" 드롭다운으로 바꿉니다.
- **점진적으로 보여 줍니다.** 기본 표는 핵심 열 몇 개만 보여 주고, 열 구성은 사용자가 고르게 합니다. 도움말은 화면당 하나(도움말 패널, 툴팁)입니다.

## 4. 공통 원칙(도입할 디자인 규칙)

1. **화면과 카드마다 강조 버튼은 하나만 둡니다.** 강조색은 `btn primary` 하나만 씁니다(`tc-i go`, `mt-go`의 강조색은 지웁니다). 목록 줄에는 강조 버튼을 두지 않습니다.
2. **버튼은 3단계로 나눕니다.** 강조(채움), 보조(테두리), 텍스트 링크 세 가지만 씁니다. 위험한 동작(`danger`)은 확인 시트 안에서만 보입니다. 크기는 휴대폰 44px, PC 32px 두 가지입니다.
3. **줄을 누르면 상세가 열립니다.** 선수, 스태프, 시설, 제안 줄은 줄 전체가 버튼입니다. 줄 안에 따로 버튼을 두지 않고, 필요하면 오른쪽 끝에 `⋯` 하나만 둡니다.
4. **부가 동작은 `⋯` 메뉴로 옮깁니다.** 매물 지정, 트레이드 불가, 사진 고치기, 계약 해지, 정리 모드 같은 동작은 화면이나 시트 오른쪽 위 `⋯`에 넣습니다.
5. **필터는 컨트롤 하나로 접습니다.** 목록 위에는 `[검색] [필터 ▾ (조건 수)] [정렬 ▾]` 한 줄만 둡니다. 칩은 적용된 조건을 요약할 때만 씁니다. 야수/투수처럼 꼭 필요한 두 갈래만 세그먼트로 남깁니다.
6. **탭은 최대 2단계입니다.** 메뉴(하단 탭이나 사이드바) 다음에 화면 위 탭 한 줄이 끝입니다. 그보다 깊은 단계는 같은 화면 안의 `보기 ▾`, 세로 스크롤 구역, 상세 시트로 바꿉니다. `inTabs()` 안에 `inTabs()`를 넣지 않습니다.
7. **휴대폰은 하단 동작 바를 둡니다.** 시트나 작업 화면의 대표 동작(협상 제안, 지명, 채용, 저장)은 하단 탭 바로 위에 고정합니다. 본문 위쪽에는 동작 버튼을 두지 않습니다.
8. **도움말은 화면당 하나입니다.** 패널마다 붙은 `i`를 지우고, 화면 제목 옆 `?` 하나로 "이 화면 설명" 시트를 엽니다. 수치 설명은 숫자를 눌렀을 때 툴팁으로 보여 줍니다.
9. **같은 동작에는 같은 라벨을 씁니다.** 협상 열기는 `협상`, 제안 보내기는 `제안하기`, 영입 확정은 `계약`, 스태프는 `채용`과 `해지`, 닫기는 `닫기`, 이동은 `‹ 뒤로`로 통일합니다. 라벨 사전은 `src/ui/components/`에 상수로 둡니다.
10. **이동 경로는 하나만 둡니다.** PC 사이드바와 휴대폰 메뉴, `SUBS`가 같은 표(`NAV`)에서 만들어지게 합니다. 같은 곳으로 가는 상단 아이콘과 하단 탭이 겹치면 하나를 지웁니다.

## 7. 자주 하는 일과 지금의 탭 수

휴대폰 기준이며, 첫 화면(홈)에서 출발해 끝날 때까지 탭한 횟수입니다. 코드 흐름과 화면을 보고 셌습니다. "n"은 고를 선수나 값의 수입니다.

| 할 일 | 지금 경로 | 지금 탭 수 | 목표 |
|---|---|---|---|
| 하루 진행 | `진행하기`. 다만 확인할 소식이 있으면 첫 탭이 소식함으로 보내고, 소식을 하나씩 열어야 합니다. | 1, 소식 있으면 1+2×소식 수 | 1, 소식은 한 장씩 넘기며 처리 |
| 선수 확인 | 선수단 → 줄 | 2 | 2(유지) |
| 선수 계약 연장 | 선수단 → 줄 → `연장 협상` → `제안` | 4 | 4(동작 위치만 하단 바로) |
| FA 계약(비시즌) | 영입·계약 → (FA 시장이 기본) → 줄 `협상` → `협상실 열기` → 금액 조정 n → `제안` | 4+n. PC는 버튼이 잘려 오른쪽 카드로 돌아가야 합니다. | 3+n(줄 → 협상 시트 → 제안) |
| 트레이드 제안 | 트레이드 → (포지션이 필요하면 `검색·필터 설정` → 칩) → `협상 시작` → 보낼 선수 n → `제안 확인` → `제안` | 4+n, 필터를 쓰면 6+n | 4+n(필터 ▾ 한 번) |
| 들어온 제안 처리 | 소식함 → 소식 → 버튼, 또는 트레이드 → 제안·매물 → 카드 버튼 5개 중 하나 | 3 | 2~3, 카드 버튼 1개와 ⋯ |

| 신인 지명(내 차례) | 영입·계약 → 신인 드래프트(하위 탭 가로 스크롤) → 후보 목록 → 줄 → `지명` | 5 | 3 |
| 재정 확인 | 메뉴 → 재정 | 2 | 2 |
| 시설 공사 | 메뉴 → 시설 투자 → 시설 종류 → 세부 → 결제 방식 버튼 | 5 | 4(시설 카드 → 시트 → 결제 방식 → 확정) |
