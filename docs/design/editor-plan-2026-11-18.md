# 선수·구단 에디터 기획 (비공개 준비) — 2026-11-18

상태: 기획 단계. 구단주 결정 11-18 — "다른 작업 먼저, 에디터는 기획해 두고 만들어도 공개하지 않는다."

## 1. 배경
- 카페 요청 다수(코가 11-18 "에디터 언제?", 국사왕 "KBO 레전드 팀").
- 11-17 결정: 능력치 에디터 없음, 이름·얼굴·등번호 바꾸기 + 일괄 수정(CSV)만 제공(src/ui/players/72_cosmetic.js).
- 고려 사항: 재미 훼손, 래더·서버 기록 공정성, 플레이스토어·스팀 출시, 유료화 가능성.

## 2. 원칙
1. 기본 게임은 그대로. 에디터는 켜야만 쓰는 선택 기능.
2. 세이브 단위 '편집됨' 표시(G.edited)가 핵심. 한 번 붙으면 영구.
   - 래더 자동 등록·서버 기록·업적·명예의 전당·클라우드 공개 기록에서 자동 제외.
3. 공식 데이터는 가상 구단·가상 선수 유지. 실명 데이터 배포·홍보 금지, 유저가 넣은 이름은 서버로 공개하지 않음.
4. 공개 전까지 숨김: 기능 플래그(예: G/설정 밖의 빌드 플래그 + 관리자 해제 코드). 일반 유저 화면에 진입점 없음.

## 3. 범위(안)
| 구분 | 내용 | 무료/유료(안) |
|---|---|---|
| 이름·얼굴·등번호 | 지금 기능 | 무료(유지) |
| 데이터 파일 가져오기/내보내기 | 리그 데이터 JSON | 무료 검토 |
| 시작 전 에디터(커스텀 리그) | 새 게임 생성 시 구단·선수·능력치·계약 편집 | 유료 후보 |
| 진행 중 커미셔너 모드 | 진행 세이브에서 능력치·계약·부상·구단 편집 | 유료 후보 |

## 4. 유료화 전제
- 웹은 익명이라 구매 확인 수단 없음 → 유료는 스팀 DLC·플레이스토어 인앱 결제에서만.
- 웹 공개 여부는 출시 방향 확정 뒤 결정.

## 5. 기술 메모
- 편집 작업은 모두 공통 함수(edPlayer/edTeam)로, 엔진 R() 호출 없음(11-09b 유지).
- 능력치 변경 시 파생값(OVR·POT·시장가치·스카우트 관찰값) 다시 계산 경로 정리 필요.
- 래더: ulAuto·수동 등록·컵 신청에서 G.edited 검사. 서버 측도 덱에 edited 표시가 있으면 거부.
- 내보내기 파일에는 실명 여부와 무관하게 서버 업로드 경로 없음.

## 6. 남은 결정
1. 무료/유료 경계(위 표).
2. 공개 시점(정식 출시와 함께 vs 웹 선공개).
3. 커스텀 리그 범위(구단 수·리그 구조까지 편집할지).
4. 편집됨 세이브용 '자유 래더'를 따로 둘지.

## 7. 순서(안)
1. G.edited 표시 + 래더·기록 제외(작음, 비공개로 먼저 넣어 둘 수 있음).
2. 커미셔너 모드 핵심(선수 능력치·계약) — 숨김 플래그 뒤.
3. 시작 전 에디터·데이터 파일.
4. 출시 결제 연동.
