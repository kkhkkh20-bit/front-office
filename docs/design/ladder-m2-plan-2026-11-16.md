# 단장 대전(래더 2안) 기획서 — 2026-11-16

> **"이번 주 선수 풀에서 연봉 한도 안으로 내 구단을 짜서 제출하면, 비슷한 실력의 단장 8~10명과 한 리그로 묶입니다. 리그는 내 기기에서 돌아가고, 순위대로 점수가 오릅니다."**

참고한 게임: 컴투스프로야구 매니저 래더(덱 제출 → 매칭 → 자동 리그), OOTP Perfect Team, 판타지 야구 샐러리캡 리그.

확정된 방향:
- 2안(단장 대전)을 먼저 합니다.
- 구단은 **예산 드래프트 구단만** 받습니다. 커리어 구단은 받지 않습니다.
- 방식은 **리그 팩**입니다. 서버는 구단을 묶어 주기만 하고, 경기는 각자 기기에서 돌립니다.

---

## 1. 한 주의 흐름

| 순서 | 사용자 | 서버 |
| --- | --- | --- |
| 1. 시즌 시작(월) | 이번 주 선수 풀을 봅니다 | 시즌 id(예: `L2026W47`)만 알립니다. 선수 풀은 시즌 id로 기기에서 똑같이 만들어집니다 |
| 2. 구단 만들기(월~목) | 연봉 한도 안에서 26명과 감독을 고르고, 타순·수비·선발·마무리·필승조를 정해 제출합니다. 마감 전에는 몇 번이든 고칠 수 있습니다 | 검증하고 저장합니다(선수 id와 방침만, 약 1KB) |
| 3. 리그 묶기(목 밤) | — | 점수가 비슷한 8~10개 구단을 한 **리그 팩**으로 묶고, 팩 시드를 정합니다 |
| 4. 리그 보기(금~일) | 팩을 받아 기기에서 시즌을 돌립니다. 약 3초면 끝나고, 순위·경기 점수·기록 1위를 봅니다 | — |
| 5. 결과 확정 | 결과 해시를 자동으로 보냅니다 | 같은 팩 사람들의 해시를 맞춰 보고 점수·등급을 올립니다 |

같은 팩이면 누가 돌려도 결과가 같습니다. 그래서 "내 기기에서 돌렸더니 우리가 1등"은 불가능합니다. 같은 리그 10명이 똑같은 순위표를 봅니다.

## 2. 규칙(1단계에서 구현됨)

| 항목 | 규칙 |
| --- | --- |
| 선수 풀 | 시즌마다 새로 380명, 감독 12명. 본게임 선수 생성 규칙 그대로이고, 얼굴도 나옵니다 |
| 1군 | 26명. 투수 11~14명 |
| 포지션 최소 | 포수 2, 유격수·2루수·3루수·중견수 각 1 |
| 운영 | 타순 9자리와 수비 위치, 선발 5명(선발형만), 마무리 1명, 필승조 최대 3명, 감독 1명 |
| 연봉 | 합이 시즌 한도 이하 |
| 구단 이름·색 | 이름 12자 이내 |
| 경기 | 본게임과 같은 `simGame`. 구장 규격은 모든 자리가 같습니다 |
| 일정 | 원형 순환. 하루에 구단마다 한 경기. 맞대결 횟수로 경기 수를 정합니다 |

검증 코드(`src/core/ladder.mjs`)는 화면과 서버가 똑같이 씁니다. 화면에서 통과한 구단은 서버에서도 통과합니다.

## 3. 실력과 운

**실력이 나오는 곳**
- 한도 안에서 가성비 좋은 선수를 찾는 눈. 능력 대비 연봉이 싼 선수가 매주 다릅니다.
- 포지션과 좌우 균형, 선발과 불펜 배분.
- 감독 성향과 명단의 궁합.
- 다른 단장들이 많이 고르는 구성(메타)을 읽고 대응하는 것.

**운을 줄이는 장치**

| 장치 | 내용 |
| --- | --- |
| 한 리그에서 많은 경기 | 측정한 한 경기 승률은 전력 차 2.6일 때 강한 쪽이 .622입니다. 30경기를 하면 강한 쪽이 91% 이깁니다. 7경기면 75%에 그칩니다 |
| 점수 | 순위만으로 올리지 않고, 기대 순위와의 차이를 반영합니다(Glicko 방식). 한 주 운은 점수에 작게만 남습니다 |
| 등급 | 브론즈·실버·골드·다이아·챔피언. 시즌(4주)이 끝나면 한 등급 내려서 다시 시작합니다 |
| 공정성 | 돈이나 플레이 시간으로 전력을 살 수 없습니다. 모두 같은 풀, 같은 한도입니다 |

## 4. 부정 방지

| 공격 | 대응 |
| --- | --- |
| 능력치를 고친 선수 | 서버는 선수 id만 받습니다. 능력은 시즌 id로 만든 풀에서 읽습니다 |
| 한도 초과·명단 규칙 위반 | 서버가 같은 검증 코드로 거절합니다 |
| 결과 조작 | 같은 팩 사람들이 보낸 해시가 다수와 다르면 버립니다. 해시가 갈리거나 한 명만 보냈으면 서버 쪽 실행기(GitHub Actions)가 그 팩을 다시 돌려 정합니다 |
| 여러 계정으로 점수 올리기 | 같은 기기 번호끼리는 같은 팩에 넣지 않습니다. 경기를 사용자가 정하지 않으니 져 주기도 안 됩니다 |
| 보상 노리기 | 보상은 칭호와 배지만 줍니다. 본게임에는 영향이 없습니다 |

## 5. 서버

- Cloudflare Worker와 D1(SQLite)을 씁니다. 경기는 서버에서 돌리지 않습니다. 묶기·검증·점수 계산만 합니다.
- 구단 스냅샷은 1KB 안팎입니다. 선수 풀은 기기에서 만들어지므로 내려받지 않습니다.
- 개인 정보는 닉네임(2~12자, 금칙어 필터)과 기기 무작위 번호만 받습니다. 이메일·로그인은 없습니다.

| 끝점 | 내용 |
| --- | --- |
| `GET /api/duel/season` | 이번 시즌 id, 연봉 한도, 마감 시각 |
| `PUT /api/duel/club` | 구단 제출·수정(마감 전까지) |
| `GET /api/duel/pack?device=` | 내 리그 팩(묶인 뒤) |
| `POST /api/duel/result` | 결과 해시 제출 |
| `GET /api/duel/me?device=` | 내 점수·등급·지난 리그 |
| `GET /api/duel/board?tier=` | 등급별 상위 100 |

비용: 사용자가 많지 않은 동안은 무료 한도 안에 들어올 가능성이 큽니다. D1을 안정적으로 쓰려면 Workers 유료($5/월)를 권합니다. 정확한 한도는 배포 전에 다시 확인합니다.

## 6. 화면

처음 화면에 **"단장 대전"** 버튼 하나만 둡니다. 화면은 넷입니다.

1. **대전 홈**: 내 등급·점수, 이번 주 마감까지 남은 시간, 지난 리그 결과 한 줄(예: "10팀 중 3위, +18점"), "구단 만들기" 버튼.
2. **구단 만들기**(1단계에서 만듦): 왼쪽은 선수 풀(포지션·연봉 거름, 정렬), 오른쪽은 내 26명과 남은 한도, 아래는 감독과 방침입니다. 자동 편성과 연습 30경기·연습 리그도 있습니다.
3. **리그 결과**: 순위표, 경기 점수, 기록 1위(타율·홈런·타점·OPS·평균자책·승·세이브), 다른 구단 명단 보기.
4. **순위표**: 등급 탭, 상위 100과 내 주변.

PC는 페이지 스크롤 없이 한 화면에 들어오게 합니다. 목록만 안쪽에서 스크롤합니다.

## 7. 진행 상황

**1단계: 끝났습니다(브랜치 `claude/ladder-m2`, 화면은 숨김 `LADDER_ON=false`).**
- 시즌 선수 풀: 시즌 id만으로 같은 380명과 감독 12명이 나옵니다.
- 구단 스냅샷·검증, 시리즈, 리그 팩 시즌.
- **같은 팩이면 같은 결과**입니다. 노드와 크롬의 결과 해시가 일치했습니다.
- 10구단 팩 한 시즌이 PC에서 약 3초 걸립니다. 느린 휴대폰은 5초 안쪽으로 추정합니다(아직 측정하지 않았습니다).
- 구단 만들기 화면, 연습 경기와 연습 리그(이 기기에만 저장).
- 규칙 점검 `[단장 대전]` 5개.

**남은 위험**
- **브라우저 간 계산 차이.** 크롬과 노드는 일치를 확인했지만, 사파리(아이폰)와 파이어폭스는 아직 시험하지 않았습니다. `Math.exp`·`Math.pow` 같은 함수는 엔진마다 마지막 자리가 다를 수 있습니다. 그러면 같은 팩이라도 해시가 갈립니다.
  - 대응: 2단계 전에 아이폰 사파리에서 같은 팩을 돌려 비교합니다.
  - 다르게 나오면 경기 계산에 쓰는 수학 함수를 직접 만든 결정적 버전으로 바꿉니다.
  - 그래도 갈리는 팩은 4절의 서버 재실행으로 정합니다.

## 9. 정할 것

1. **본게임 난수.** 1단계에서 엔진 난수에 시드를 넣어 저장과 함께 저장되게 했습니다. 이걸 본게임에도 켜면, 저장을 다시 불러와도 같은 결정이면 같은 미래가 나옵니다. 장점은 새로고침으로 결과를 다시 뽑는 세이브 스컴이 의미 없어진다는 것입니다. 단점은 "다시 해 보기"로 다른 결과를 보던 재미가 사라진다는 것입니다.
   - 권장: 켭니다. 대전 모드는 이것과 관계없이 항상 결정적입니다.
2. **주기와 리그 크기.**
   - 권장: 매주 한 리그(월~목 제출, 목 밤 묶기, 금~일 결과), 한 리그 8~10팀.
   - 경기 수는 팀당 30~36경기(맞대결 4번)를 권합니다. 운이 충분히 줄고 실행도 3초 안팎입니다.
3. **서버 비용.** Workers 유료($5/월)와 D1 사용 여부. Cloudflare API 토큰은 배포 설정에 필요합니다.
4. **사람이 적을 때.** 마감 때 8명이 안 모이면 AI 자동 편성 구단으로 채울지, 정한 시각까지 기다릴지.
   - 권장: AI로 채웁니다. AI 구단은 점수가 없습니다.
5. **보상.** 칭호·배지만 줍니다(권장). 본게임 보상은 부정 동기를 키웁니다.
6. **닉네임.** 익명 닉네임과 기기 번호로 시작하고, 기기 옮기기 코드로 이어 갈 수 있게 합니다(권장).
