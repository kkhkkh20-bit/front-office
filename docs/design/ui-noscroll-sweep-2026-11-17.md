# 화면 맞춤 전수 점검 (2026-11-17)

구단주 원칙(11-16): "최대한 드래그 안 하게 화면 구성", "드래그 할 거면 탭을 만들듯". PC는 화면 하나에 들어가야 하고(페이지 스크롤 없음, 상자 안 스크롤바 없음), 넘치면 탭으로 나눕니다. 휴대폰도 스크롤을 줄이고 긴 화면은 탭으로 나눕니다. 자주 쓰는 동작은 탭 뒤로 숨기지 않습니다.

이 문서는 고치기 전 상태(`claude/ui-phase3` 86036d2d 빌드)를 잰 결과입니다. UI 3단계 3-0의 작업 목록으로 씁니다.

## 측정

- 도구: `node tools/measure-ui-fit.cjs <출력 폴더> [mid,off] [크기들]`. 상태 파일은 `tools/measure-ui-density.cjs`가 만든 `state-mid.json`·`state-off.json`(`STATE_DIR`)을 씁니다.
- 상태: 시즌 중(2026-06-20), 비시즌(2026-11-06, FA 협상 1일째). 3단계 계획의 측정 상태와 같습니다.
- 크기: 1366×768, 1440×900, 1874×915, 1920×1080, 390×844.
- 화면: 모든 상단 탭과 하위 탭(`NAV`·`SUBS`·`MFOLD`) 125개, 상세 창 15개(선수 우리 투수·타자·다른 팀, 감독, 코치 2명, 스카우트, 분석원, 구단주, 팀 카드, 트레이드 협상, 연장 협상, FA 협상(비시즌), 경기 입장, 전체 메뉴). 화면당 크기 5개 × 상태 2개.
- 지표
  - 페이지 넘침: 화면을 넘는 높이(px). 문서 스크롤과 화면 대부분을 차지하는 주 스크롤 칸 중 큰 값입니다.
  - 안쪽 스크롤: 주 스크롤 칸이 아닌데 세로로 넘쳐 스크롤바가 생긴 칸 수.
  - 잘림: `overflow:hidden`으로 내용이 잘린 상자 수.
  - 겹침: 서로 겹친 상자 쌍 수.
  - 빈 늘어남: 높이 200px 넘는 상자에서 내용 아래 빈 부분이 35% 넘는 상자 수(최대 비율).
- 점수: PC 페이지 넘침 100px당 3점, 안쪽 스크롤 칸당 6점(휴대폰 3점), 잘림 5점, 겹침 8점, 빈 늘어남 3점(휴대폰 1점). 휴대폰 페이지 넘침은 4화면을 넘는 만큼만 셉니다.
- 스크린샷(DSF 1): `scratchpad/ui3/before/{mid|off}-{폭}x{높이}-{화면}.png`.

## 고칠 방향

1. **상세 창(선수·감독·코치·직원)**: 한 화면에 맞춥니다. 들어가지 않는 구역은 창 안 탭으로 나눕니다. 선수 상황판은 화면 높이를 넘으면 낮은 순서부터 상자를 접고(경력 → 수비 위치/구속 → 능력 변화 선 → 보고서 근거 줄 → 감독 의견 → 계약·신분 → 시즌 통계), 접힌 내용은 위 탭(기록·관리·경력·수상)에 그대로 있습니다.
2. **재정·구단주·구단 정보·훈련 같은 대시보드형 화면**: 상자마다 스크롤하지 않게 상자 수를 줄이고, 남는 상세는 이미 있는 하위 탭으로 옮깁니다.
3. **긴 목록(소식, 리그 소식, FA·계약·이적 표, 연대기)**: 목록 자체가 긴 화면은 표 한 곳만 스크롤하거나 쪽 나눔(`twPager`)으로 바꿉니다. 페이지와 표가 같이 스크롤되는 이중 스크롤을 없앱니다.
4. **휴대폰**: 4화면을 넘는 화면(소식함, 훈련·육성, 스태프 시장, 코치진)은 구역 탭이나 쪽 나눔으로 줄입니다.
