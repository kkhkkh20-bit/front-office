# 유저 래더·프런트컵 서버 운영 메모

2026-11-17 기준입니다. 서버 코드: `worker/uladder.js`(래더), `worker/cup.js`(프런트컵), `worker/kvcache.js`(캐시·횟수 제한), `worker/index.js`(기기 옮기기·상태 확인).

## 1. 래더는 이렇게 돌아갑니다

- 경기는 모두 유저 기기에서 돕니다. 서버는 경기를 돌리지 않습니다.
- 서버(Cloudflare Worker + Workers KV `SAVE_KV`)가 보관하는 것은 두 가지뿐입니다.
  - 덱: 세계 id마다 하나(`ulD:세계id`, 약 8KB, 사진은 빼고 저장). 메타데이터에 팀명·연도·OVR·단계·숨김 여부가 있습니다.
  - 색인: 단계별 덱 목록 한 키(`ulIdx`). 단계마다 최근 등록 500개까지 둡니다. 상대 고르기와 단계별 덱 수는 이 색인 하나로 계산합니다.
- 유저 흐름은 다음과 같습니다.
  1. 덱 등록: 덱 본문과 색인을 씁니다. 바뀐 것이 없으면(본문 해시와 단계가 같으면) 아무것도 쓰지 않습니다.
  2. 리그 시작: 색인에서 내 OVR과 가까운 같은 단계 덱 9개를 골라 받습니다. 경기는 기기에서 돕니다.
  3. 리그 종료: 단계가 바뀐 경우에만(승격·강등) 덱 메타데이터와 색인을 고칩니다. 잔류면 아무것도 쓰지 않습니다.
- 서버에 연결할 수 없거나 등록이 거절돼도 그 기기의 리그는 그대로 됩니다. 받은 덱이 모자라면 우승 덱과 AI 구단이 채웁니다.
- 기기 옮기기(`/api/transfer`)와 프런트컵 신청도 같은 KV를 씁니다. 아래 한도는 셋이 함께 씁니다.

## 2. 운영자가 볼 것

설정 › 정보 맨 아래 '관리자' → 관리자 페이지 맨 위 상태 줄에 다음처럼 나옵니다.

> 서버 연결 OK · 관리자 키 맞음 · 대회 … · 래더 덱 n개 · 오늘 쓰기 약 n회

- '오늘 쓰기'는 래더가 오늘(UTC 0시 = 한국시간 오전 9시부터) KV에 쓴 횟수의 추정치입니다. 기기 옮기기와 프런트컵 신청은 들어 있지 않습니다. 여러 서버가 동시에 고치면 조금 덜 셀 수 있습니다.
- 무료 요금제라면 이 숫자가 **700회**를 넘는 날이 이어질 때 유료 전환을 검토하면 됩니다(기기 옮기기·대회 몫을 남겨 둡니다).
- 정확한 사용량은 Cloudflare 대시보드 › Storage & Databases › KV › 해당 namespace › Metrics에서 볼 수 있습니다.
- 서버가 살아 있는지만 보려면 `/api/health`를 열면 됩니다. KV를 전혀 쓰지 않습니다.
- 관리자 API로 직접 보려면 `GET /api/admin/usage`(헤더 `Authorization: Bearer 관리자키`)를 씁니다.

## 3. 한도와 감당할 수 있는 리그 수

Cloudflare 공식 문서(KV Pricing·Limits, 2026-11-17 확인)의 값입니다.

| 항목 | Workers Free(무료) | Workers Paid(월 5달러) |
| --- | --- | --- |
| KV 읽기 | 하루 100,000회 | 월 1,000만 회 포함, 이후 100만 회당 0.5달러 |
| KV 쓰기 | 하루 1,000회 | 월 100만 회 포함, 이후 100만 회당 5달러 |
| KV 삭제 | 하루 1,000회 | 월 100만 회 포함 |
| KV 목록 | 하루 1,000회 | 월 100만 회 포함 |
| 같은 키 쓰기 | 초당 1회 | 초당 1회 |

무료 한도는 매일 UTC 0시(한국시간 오전 9시)에 다시 채워집니다. Worker 요청 수(무료 하루 10만 회)와 요청당 CPU 시간(무료 10ms)도 따로 한도가 있습니다.

### 동작당 KV 사용량

| 동작 | 예전 | 지금 |
| --- | --- | --- |
| 단계표 보기(`/tiers`) | 목록 5회 이상 | 캐시면 0, 아니면 읽기 1 |
| 리그 시작(`/opp`) | 목록 1회 + 읽기 최대 9 | 읽기 최대 9(+색인 1, 보통 캐시) |
| 덱 등록(바뀜) | 읽기 1 + 쓰기 2 (+삭제 1) | 읽기 2 + 쓰기 2 |
| 덱 등록(그대로) | 읽기 1 + 쓰기 2 | 읽기 2, 쓰기 0 |
| 리그 종료 잔류 | 읽기 1 + 쓰기 2 | 읽기 1, 쓰기 0 |
| 리그 종료 승강 | 읽기 1 + 쓰기 2 + 삭제 1 | 읽기 2 + 쓰기 2 |
| 덱 지우기 | 읽기 1 + 삭제 2 | 읽기 2 + 삭제 1 + 쓰기 1 |
| 색인 다시 만들기(하루 1번·색인이 없을 때) | 없음 | 목록 1회/1000덱 + 쓰기 1 |

### 하루에 감당할 수 있는 리그 수(추정)

가정: 리그 한 번에 단계표 1번, 리그 시작 1번, 리그 종료 1번. 승강 확률 약 40%, 덱을 바꿔 다시 등록하는 일은 리그 3번에 1번.

- 예전: 리그마다 목록 6회(단계표 5 + 리그 시작 1)라 **무료로 하루 약 160리그**에서 목록 한도에 걸렸습니다.
- 지금: 리그마다 쓰기 약 1.5회(승강 0.8 + 재등록 0.7), 목록 0회, 읽기 약 12회입니다.
  - **무료: 하루 약 600리그**(쓰기 한도. 기기 옮기기·대회 몫 100회를 남긴 값). 모든 리그가 승강하고 매번 덱을 바꾸는 최악이면 약 250리그입니다.
  - **유료(월 5달러): 하루 약 2만 리그**까지 포함량 안에서 됩니다(월 쓰기 100만 회 ÷ 30일 ÷ 1.5). 그 이상은 리그 1만 번에 약 0.08달러가 더 듭니다.
  - 읽기는 무료로도 하루 약 8,000리그까지 여유가 있어 먼저 걸리지 않습니다.
- 색인 키 하나를 모두가 고치므로, 하루 5만 리그를 넘기면(같은 키 초당 1회 쓰기에 가까워짐) 단계별 키로 나누는 작업이 필요합니다.

## 4. 한도에 걸리면

- 무료 쓰기 한도를 넘으면 그날 오전 9시(한국시간)까지 **새 덱 등록·덱 고치기·승강 반영이 실패**합니다. 게임에는 "서버 등록은 하지 못했습니다. 이 기기 리그는 그대로 할 수 있습니다."가 나옵니다.
- 리그 시작·경기·결과는 그대로 됩니다(읽기는 따로 남아 있습니다). 승강 반영이 빠진 덱은 다음 리그를 마칠 때 다시 맞춰집니다.
- 기기 옮기기(코드 만들기)와 프런트컵 신청도 같은 쓰기 한도를 쓰므로 같은 시간 동안 실패할 수 있습니다. 대회 접수 기간에는 특히 상태 줄을 봐 주세요.
- 할 일은 둘 중 하나입니다.
  1. 아무것도 하지 않습니다. 다음 날 오전 9시에 저절로 풀립니다. 데이터는 지워지지 않습니다.
  2. Cloudflare 대시보드 › Workers & Pages › Plans에서 Workers Paid(월 5달러)로 바꿉니다. 코드는 그대로 두면 됩니다.

## 5. 서버 쪽 보호 장치(참고)

- 캐시: 단계별 수·색인·프런트컵 공개 결과·연재·명단·대회 설정은 60~600초 동안 담아 둡니다. 같은 서버 인스턴스에서 쓰기를 하면 바로 비웁니다. 다른 지역은 최대 1~2분 늦게 새 값을 봅니다. Cache API는 사용자 지정 도메인에서만 동작하고 `workers.dev` 주소에서는 동작하지 않을 수 있습니다(확인 못 함). 그때도 인스턴스 메모리 캐시는 동작합니다.
- 횟수 제한: 세계 id당 하루 덱 등록 20번(바뀐 것만 셈), 승강 반영 40번. IP당 10분에 쓰기 요청 60번(서버 인스턴스마다 따로 셈). 넘으면 "오늘은 더 등록할 수 없습니다."가 나옵니다.
- 배포 직후 첫 요청에서 색인을 덱 목록으로 한 번 만듭니다(목록 1회 + 쓰기 1). 예전 단계 색인 키(`ulT:단계:세계id`)는 더 쓰지 않습니다. 남아 있어도 문제없고, 지우려면 대시보드에서 지우면 됩니다(지우기도 한도에 들어갑니다).
