# 래더 관리자 대시보드 — 2026-11-18

구단주 요청: "관리자에 래더를 좀 더 앞의 탭으로 해 주고, 여러 통계 등 데이터를 볼 수 있게. 발전시켜 줘. 이 부분 기획해서 제대로 보기 좋게."
참고: 구단주의 GA4 대시보드(탭 · 큰 숫자 + 한 줄 설명 카드 · 먼저 확인할 것 · 평소와 다른 것 · 패치 표시선 · 용어 설명).

## 1. 자리

- 관리자 페이지 첫 탭 = **래더 현황**(기본으로 열림), 둘째 = 프런트컵.
- 래더 현황 안의 탭: 개요 · 참여·유지 · 단계·메타 · 경쟁 균형 · 플레이어 · 운영 · 상태. 맨 위에 범위(오늘 · 7일 · 30일 · 이번 시즌)와 새로고침.
- '운영' = 예전 래더 현황 화면 그대로(등록 현황 · 이상 감지 · 진행 중/끝난 리그 들여다보기 · 덱 숨김/삭제 · CSV 내보내기 · 사용량). 30초 자동 새로고침은 이 탭에서만.
- PC는 페이지가 통째로 스크롤되지 않고 칸 안에서 스크롤(넓은 칸 2 + 오른쪽 칸 1). 휴대폰 390은 위에서 아래로 쌓고 표·그림은 칸 안에서 가로 스크롤.

## 2. 탭별 내용

| 탭 | 내용 |
|---|---|
| 개요 | KPI 카드 10장(등록 덱 · 실제 플레이어 · 활성 1/7/30일 · 완료 리그 · 승격·강등 · 거절 덱 · 자동/직접/끔 · D1 쓰기 %), 카드마다 직전 같은 기간 대비. 날마다 선 그래프(활성 · 새 덱 · 완료 리그)와 패치 점선(75_patch_notes.js id의 날짜, 마우스를 올리면 제목). 먼저 확인할 것(빨강 문제 · 노랑 확인 · 파랑 참고), 평소와 다른 것(오늘 vs 직전 7일 평균, 1.5배 이상 또는 절반 이하), 플레이어 수 보는 법 |
| 참여·유지 | 깔때기(등록 → 첫 리그 → 3리그 → 승격 → 우승, 앞 조건을 모두 채운 덱만, 가장 크게 빠지는 단계 빨강) · 코호트(처음 등록한 날 × 1/3/7일 뒤에도 왔나 · 올라가 본 단계, 덱 5개 미만 흐리게) · 날짜 × 시간(한국시간) 리그 완료 열지도 · 등록 방식 |

| 플레이어 | 검색(닉네임·덱 이름·id) · 단계 · 정렬(마지막 접속·리그·승률·우승·OVR·단계·기기) · 50명씩 쪽 · CSV. 줄을 누르면 오른쪽에 자세히(덱 요약 · 등록 방식 · 기기 수 · 같은 기기 덱 수 · 최근 리그 15개 · 시즌 · 많이 만난 상대 · 숨기기/덱 삭제). 덱 본문·기기 번호 원문은 보내지 않는다 |

## 3. 플레이어 수 정의(관리자 화면에 한국어로 짧게 설명)

- **등록 덱**: `decks` 줄 수(플레이어 id마다 1개).
- **실제 플레이어(익명 id)**: 덱을 가진 서로 다른 `player_id` 수. id는 브라우저마다 만드는 익명 토큰이라, 한 사람이 기기 두 대에서 연결하지 않고 하면 두 명으로 센다.
- **기기 묶음 추정**: `ladder_reg.dev`(기기 번호의 해시 앞 16자)가 같은 덱을 하나로 본 수. 기기 표식이 없으면 플레이어 id 하나 = 하나.
- **활성 1/7/30일**: `players.last_seen` 또는 덱 갱신(`decks.at`)이 그 기간(한국시간 오늘 0시 기준) 안.
- **기기 수**: `devices` 줄 수(연결한 기기마다 1). 기기 연결한 플레이어 = `identities`가 있는 플레이어.
- **자동 · 직접 · 끔**: `ladder_reg.auto`(1 자동, 그 밖은 직접) · `ladder_reg.off = 1`.

## 4. 서버

- `GET /api/v1/admin/lstats?range=` · `GET /api/v1/admin/lplayers?q=&tier=&sort=&desc=&n=&off=` · `GET /api/v1/admin/lplayer?pid=` (worker/v1/ladstats.js). 관리자 키(CUP_ADMIN) 뒤, 읽기 전용.
- 새 표·색인 없음. 쓰기는 하나: 500 응답 때 `daily_stats`의 `err5`에 1(드물다).
- 읽기 비용(한 번 열 때): daily_stats 최근 60일(키 수 × 60) + 덱 수만큼(decks·players·ladder_reg·deck_meta, 덱당 devices·ladder_entries 색인 조회) + league_results 플레이어별 묶음(전체 결과 줄 수) + h2h 최대 3000줄. 덱 1,000개·결과 3만 줄이면 약 4~5만 줄 읽기 → 무료 하루 500만 줄의 1% 안. 화면은 탭을 열 때·범위를 바꿀 때·새로고침 단추를 누를 때만 받는다.

## 5. 표본 주의

- 덱이 30개 미만이면 '먼저 확인할 것'에 파랑 안내. 코호트 칸(그날 덱 5개 미만)과 산점도 점(리그 1개)은 흐리게.
- 이변 비율은 맞대결 당시가 아니라 지금 덱 OVR로 본 근사.
