# 3D 중계 개선 기획 (2026-11-13)

범위는 3D 중계(`src/scene3d`, `src/ui/matches`)뿐이다. 시뮬레이션·리그 운영은 다루지 않는다.
비교 기준은 OOTP류 3D 경기 화면이지만, 나란히 놓고 측정한 적은 없다. 아래 "차이"는 기능 유무로만 적는다.

## 1. 지금 상태

| 영역 | 있는 것 | 없는 것·약한 것 |
|---|---|---|
| 재생 구조 | 경기 기록(공 단위)을 그대로 3D로 재생, 일시정지·배속·하이라이트 | 리플레이, 장면 사이 컷 전환 |
| 카메라 | 홈 뒤 기본, 타구 추적·줌, 송구 때 받는 야수 선행 프레이밍, 전광판 보기 | 중견수 쪽 투구 카메라, 주자·홈런 타자 전용 컷, 느린 화면 |
| 투구·타격 | 세트 포지션, 팔 높이 3종, 레그킥·골반 선행·배트 지연·팔 뻗기·마무리, 번트, 시선 추적 | 선수별 고유 폼, 체크 스윙, 파울 타구별 스윙 차이, 몸쪽 공 피하기 |
| 수비 | 땅볼·뜬공·라이너·송구·뻗어 잡기·태그·달려가며 잡기, 포수 미트 위치 | 다이빙·점프 캐치, 펜스 플레이, 중계 플레이(컷오프), 백업 이동 |
| 주루 | 가속, 상체 기울임, 리드 자세, 슬라이딩 타이밍 | 헤드 퍼스트 슬라이딩, 베이스 돌 때 몸 기울임, 귀루 |
| 심판 | 4심 배치, 주심 보호구, 스트라이크·아웃·세이프 동작(가까운 심판이 플레이 쪽으로 돌아서 판정) | 음성, 파울·홈런 신호, 체크 스윙 어필 |
| 인물·구장 | 선수 모델 1종에 유니폼 색, 구장 1종, 관중석 인스턴스 | 체형·키 차이, 얼굴, 구장별 형태, 더그아웃 선수, 볼보이 |
| 소리 | CC0 타격음·미트음·관중 반응 | 심판 콜, 응원가, 장내 아나운서 |
| 연출 | 캐스터 자막, 이닝 시작 표시, 종료 카드, 벤치 클리어링 | 득점·홈런 세리머니, 투수 교체 등장, 끝내기 연출 |

동작 품질의 한계: 클립은 손으로 키를 잡은 것이고, 그 위에 매 프레임 보정(IK·시선·가동범위)을 얹는다. 관절 각도와 위치는 교본 수치에 맞췄지만, 무게 이동과 클립 사이 전환은 모션캡처만큼 자연스럽지 않다.

검증의 한계: 개발 환경이 소프트웨어 WebGL이라 실시간 재생을 볼 수 없다. 시계를 40ms씩 넘기는 프레임 캡처와 관절 수치로만 확인한다. 실제 기기에서의 프레임 속도와 체감은 확인된 적이 없다.

## 2. 우선순위 원칙

1. 매 타석 보이는 것 먼저(투구·타격·포구 화면) → 가끔 보이는 것(도루·병살) → 드물게 보이는 것(벤치 클리어링).
2. 화면에서 차지하는 크기가 큰 것 먼저. 외야수 손가락보다 홈 플레이트 주변.
3. 새 클립이 필요한 일은 보정 층으로 풀 수 있는 일보다 뒤. 손 키 클립은 품질 위험이 크다.
4. 각 항목은 "실제 재생 캡처 + 수치" 두 가지로 확인할 수 있어야 착수한다.

## 3. 단계별 계획

### 1단계 — 보정 층만으로 가능(에셋 추가 없음)

| 항목 | 내용 | 확인 방법 |
|---|---|---|
| 주심 가시성 | 판정 순간 자막을 잠깐 위로 올리거나 카메라를 0.3~0.5m 높임. 둘 중 하나를 고를 것 | 판정 프레임에서 주심 팔이 자막 밖에 있는지 |
| 포수 송구 전 일어서기 | 현재 0.24초 고정 구간. 엉덩이 높이·무릎 각을 매끄럽게 잇기 | 엉덩이 높이 곡선에 꺾임이 없는지 |
| 슬라이딩 자세 | 발 먼저 슬라이딩에서 상체 눕힘·앞다리 뻗기·뒷다리 접기 보정 | 접지 프레임에서 엉덩이·앞발 높이 |
| 베이스 돌기 | 1→2루 등 꺾이는 구간에서 몸을 안쪽으로 기울임(속도·곡률에 비례) | 기울기 각과 진행 방향 변화율 |
| 수비 백업 | 송구 때 받는 야수 뒤로 한 명이 이동(1루 송구 시 포수·우익수 등) | 송구 프레임에서 백업 위치 |
| 타자 반응 | 볼 판정 뒤 배트 내리기, 삼진 뒤 고개 숙임(짧은 보정 자세) | 프레임 캡처 |
| 판정 신호 확장 | 파울(두 팔 위로), 홈런(검지 돌리기) | 손 위치 수치 |

### 2단계 — 카메라·연출(코드만)

| 항목 | 내용 | 위험 |
|---|---|---|
| 장면 컷 | 플레이가 끝난 뒤 1초 안팎의 반응 컷(투수·타자·더그아웃 중 하나) | 배속 재생과 충돌. 배속 2 이상에서는 끔 |
| 홈런 연출 | 타구 추적 → 낙하 → 베이스 도는 타자 컷 → 홈 | 길이. 건너뛰기 필요 |
| 리플레이 | 직전 플레이의 actor·공 궤적을 기록해 다른 각도·0.5배로 재생 | 상태 기록 구조를 새로 만들어야 함. 가장 큰 작업 |
| 투구 카메라 선택 | 홈 뒤(현재) / 중견수 쪽 선택 | 중견수 카메라는 투구 위치판·자막 배치를 다시 잡아야 함 |
| 득점 순간 | 홈 밟는 주자 줌 + 스코어 버그 강조 | 낮음 |

### 3단계 — 에셋이 필요한 일

| 항목 | 필요한 것 | 비고 |
|---|---|---|
| 모션캡처 클립 교체 | 투구·스윙·수비·슬라이딩 클립(라이선스 확인된 것) | CMU 자료는 야구 동작이 적고 품질이 맞지 않았음(124_08 번트만 사용). 유료 팩 또는 직접 촬영이 현실적 |
| 다이빙·점프 캐치 | 새 클립 2~4개 | 손 키로 만들면 어색할 가능성이 높음 |
| 체형 차이 | 뼈 길이·몸통 굵기 스케일(선수 키·체중 반영) | 에셋 없이도 가능하지만 보정 층의 IK 길이 가정을 전부 점검해야 함 |
| 구장별 형태 | 담장 거리·높이는 이미 엔진 값이 있음. 모델을 변형하거나 구장별 모델 | 담장만 변형하는 방식이 싸다 |
| 심판·장내 음성 | 한국어 콜 음원(CC0 또는 직접 녹음) | 이전 조사에서 쓸 만한 CC0 한국어 콜은 못 찾음 |
| 더그아웃·불펜 인원 | 앉은 자세 클립 1~2개 | 낮음 |

### 4단계 — 실제 기기 확인(사람이 해야 함)

- 휴대폰·저사양 PC에서 프레임 속도, 배속별 체감
- 동작이 "야구로 읽히는지"에 대한 판단. 수치로는 대신할 수 없다
- 확인 결과에 따라 1~2단계 항목의 순서를 다시 정한다

## 4. 하지 않는 것

- 실제 선수의 초상·고유 폼 재현(라이선스)
- 물리 시뮬레이션으로 결과를 바꾸는 일. 3D는 기록을 재생만 한다
- 자막 모양 변경(기존 둥근 띠 유지), 화면 장식 추가

## 5. 측정 기준(완료 판단)

- 실제 재생 캡처에서 관절 꺾임·몸 관통·순간 이동이 0건
- 판정 동작은 판정 프레임 기준 ±120ms 안에 시작
- 공과 글러브·미트 접촉 오차 15cm 이하
- 자동 점검(`check-match3d-review`, `check-match3d-state`, `check-gameplay`, `check-pitches`) 통과
