# 3D 중계 개선 기획 (2026-11-13)

범위는 3D 중계(`src/scene3d`, `src/ui/matches`)뿐이다. 시뮬레이션·리그 운영은 다루지 않는다.
비교 기준은 OOTP류 3D 경기 화면이지만, 나란히 놓고 측정한 적은 없다. 아래 "차이"는 기능 유무로만 적는다.

## 1. 지금 상태

| 영역 | 있는 것 | 없는 것·약한 것 |
|---|---|---|
| 재생 구조 | 경기 기록(공 단위)을 그대로 3D로 재생, 일시정지·배속·하이라이트 | 리플레이, 장면 사이 컷 전환 |
| 카메라 | 홈 뒤 기본, 타구 추적·줌, 송구 때 받는 야수 선행 프레이밍, 전광판 보기 | 중견수 쪽 투구 카메라, 주자·홈런 타자 전용 컷, 느린 화면 |

| 연출 | 캐스터 자막, 이닝 시작 표시, 종료 카드, 벤치 클리어링 | 득점·홈런 세리머니, 투수 교체 등장, 끝내기 연출 |

동작 품질의 한계: 투구·타격·수비 클립 위에 매 프레임 보정(IK·시선·가동범위)을 얹는다. 관절 각도와 위치는 교본 수치에 맞췄지만, 무게 이동과 클립 사이 전환은 모션캡처만큼 자연스럽지 않다.

### 쓰지 않는 클립(11-13 확인)

`assets/match3d/player.glb`에는 클립이 118개 있고, 코드가 쓰는 것은 약 39개(투구 폼 8개 포함)다. 나머지 약 79개는 재생되는 것만 확인했고(16개는 프레임 캡처로 자세 확인), 실제 장면에 넣었을 때의 품질은 항목마다 따로 봐야 한다.

| 심판 | ump_ready, ump_strike, ump_out, ump_out_strikeout, ump_safe, ump_foul | 11-13 적용 |
| 심판(남은 것) | ump_ball, ump_fair, ump_homerun, ump_time, ump_strike_swinging, ump_set_base, ump_brush_plate, ump_new_ball, ump_huddle | 미적용 |

이 클립들이 있으므로 "새 클립이 필요하다"고 봤던 항목 상당수(점프 캐치, 헤드 퍼스트 슬라이딩, 베이스 돌기, 심판 신호)는 에셋 추가 없이 코드 연결만으로 가능하다. 아래 단계 계획은 이 전제로 다시 짰다.

검증의 한계: 개발 환경이 소프트웨어 WebGL이라 실시간 재생을 볼 수 없다. 시계를 40ms씩 넘기는 프레임 캡처와 관절 수치로만 확인한다. 실제 기기에서의 프레임 속도와 체감은 확인된 적이 없다.

## 2. 우선순위 원칙

1. 매 타석 보이는 것 먼저(투구·타격·포구 화면) → 가끔 보이는 것(도루·병살) → 드물게 보이는 것(벤치 클리어링).
2. 화면에서 차지하는 크기가 큰 것 먼저. 외야수 손가락보다 홈 플레이트 주변.
3. 모델에 이미 있는 클립을 연결하는 일이 먼저. 직접 팔다리 각도를 잡는 동작은 전용 클립이 없을 때만.
4. 각 항목은 "실제 재생 캡처 + 수치" 두 가지로 확인할 수 있어야 착수한다.

## 3. 단계별 계획

### 1단계 — 있는 클립 연결(에셋 추가 없음, 화면에 자주 보이는 순)

| 순서 | 항목 | 쓸 클립 | 필요한 코드 | 위험 |
|---|---|---|---|---|
| 1 | 투구 사이 호흡 | catcher_signs, pitcher_nod, pitcher_shake_off, batter_adjust | 공 사이 대기(현재 0.7초)에 맞춰 일부만 재생하거나, 1배속에서만 대기를 늘림 | 경기 진행 속도가 바뀜. 배속별로 꺼야 함 |
| 2 | 타석 들어서기 | batter_step_in | 타석 시작 자막 구간에 재생 후 타격 자세로 | 낮음 |
| 3 | 점프·백핸드 캐치 | catch_jump, catch_backhand | 직선타 일부의 공 도착 높이를 비행 시작 때 2.4m 안팎으로 정하고 그 타구에 catch_jump. 옆으로 뛰며 잡는 직선타는 catch_backhand | 공 높이를 비행 중에 바꾸면 궤적이 꺾이므로 UI 쪽 타구 생성에서 정해야 함 |
| 4 | 슬라이딩 종류 | slide_head, slide_hook_left/right, pop_up_head | 도루·접전에서 선수·상황별로 고름. 클립마다 이벤트 시각(dive_start·land·rest)이 달라 `slide()` 시간 계산을 클립별로 | 중간. 현재 발 슬라이딩 타이밍 점검이 있음 |
| 5 | 베이스 돌기 | run_turn, run_turn_sprint | 주자 경로가 꺾이는 지점 앞뒤에서 달리기 클립과 섞음 | 중간. 발 미끄러짐 확인 필요 |
| 6 | 견제·귀루 | pickoff, pitcher_look_runner, dive_back | 엔진에 견제 기록이 있는지 먼저 확인. 없으면 연출용으로만 | 기록에 없는 플레이를 보여주면 안 됨 |
| 7 | 포수 블로킹·높은/낮은 송구 포구 | catcher_block, catch_throw_high/low | 낮은 공·바운드 송구에 연결 | 낮음 |
| 8 | 남은 심판 신호 | ump_fair, ump_homerun, ump_ball, ump_time | 선상 타구·홈런·투수 교체 때 | 낮음 |
| 9 | 주루 코치 | coach_ready, coach_go, coach_stop | 1·3루 코치 박스에 한 명씩 | 뼈대 메시 2개 추가. 휴대폰 성능 확인 필요 |
| 10 | 대기 타석·더그아웃 | ondeck_*, bench_* | 대기 타석 1명, 더그아웃 앉은 선수 | 뼈대 메시가 많이 늘어남. 저사양 옵션 필요 |

### 2단계 — 보정 층 다듬기

| 항목 | 내용 | 확인 방법 |
|---|---|---|
| 포수 송구 전 일어서기 | 현재 0.24초 고정 구간. 엉덩이 높이·무릎 각을 매끄럽게 잇기 | 엉덩이 높이 곡선에 꺾임이 없는지 |
| 수비 백업 | 송구 때 받는 야수 뒤로 한 명이 이동 | 송구 프레임에서 백업 위치 |
| 타자 반응 | 볼 판정 뒤 배트 내리기, 삼진 뒤 고개 숙임 | 프레임 캡처 |
| 클립 전환 | 포구→송구, 달리기→슬라이딩 전환 구간의 발 미끄러짐 | 발 위치 수치 |

### 3단계 — 카메라·연출(코드만)

| 항목 | 내용 | 위험 |
|---|---|---|
| 장면 컷 | 플레이가 끝난 뒤 1초 안팎의 반응 컷(투수·타자·더그아웃 중 하나) | 배속 재생과 충돌. 배속 2 이상에서는 끔 |
| 홈런 연출 | 타구 추적 → 낙하 → 베이스 도는 타자 컷 → 홈, 3루심 홈런 신호 | 길이. 건너뛰기 필요 |
| 리플레이 | 직전 플레이의 선수·공 궤적을 기록해 다른 각도·0.5배로 재생 | 상태 기록 구조를 새로 만들어야 함. 가장 큰 작업 |
| 투구 카메라 선택 | 홈 뒤(현재) / 중견수 쪽 선택 | 중견수 카메라는 투구 위치판·자막 배치를 다시 잡아야 함 |
| 득점 순간 | 홈 밟는 주자 줌 + 스코어 버그 강조 | 낮음 |

### 4단계 — 에셋이 필요한 일

| 항목 | 필요한 것 | 비고 |
|---|---|---|
| 투구·스윙 클립 품질 | 모션캡처 클립(라이선스 확인된 것) | CMU 자료는 야구 동작이 적고 품질이 맞지 않았음(124_08 번트만 사용). 유료 팩 또는 직접 촬영이 현실적 |
| 다이빙 캐치 | 새 클립(모델에 없음) | 손 키로 만들면 어색할 가능성이 높음 |
| 체형 차이 | 뼈 길이·몸통 굵기 스케일(선수 키·체중 반영) | 에셋 없이도 가능하지만 보정 층의 IK 길이 가정을 전부 점검해야 함 |
| 구장별 형태 | 담장 거리·높이는 이미 엔진 값이 있음. 모델을 변형하거나 구장별 모델 | 담장만 변형하는 방식이 싸다 |
| 심판·장내 음성 | 한국어 콜 음원(CC0 또는 직접 녹음) | 이전 조사에서 쓸 만한 CC0 한국어 콜은 못 찾음 |

### 5단계 — 실제 기기 확인(사람이 해야 함)

- 휴대폰·저사양 PC에서 프레임 속도, 배속별 체감
- 동작이 "야구로 읽히는지"에 대한 판단. 수치로는 대신할 수 없다
- 확인 결과에 따라 1~3단계 항목의 순서를 다시 정한다

## 4. 하지 않는 것

- 실제 선수의 초상·고유 폼 재현(라이선스)
- 물리 시뮬레이션으로 결과를 바꾸는 일. 3D는 기록을 재생만 한다
- 자막 모양 변경(기존 둥근 띠 유지), 화면 장식 추가

## 5. 측정 기준(완료 판단)

- 실제 재생 캡처에서 관절 꺾임·몸 관통·순간 이동이 0건
- 판정 동작은 판정 프레임 기준 ±120ms 안에 시작
- 공과 글러브·미트 접촉 오차 15cm 이하
- 자동 점검(`check-match3d-review`, `check-match3d-state`, `check-gameplay`, `check-pitches`) 통과
