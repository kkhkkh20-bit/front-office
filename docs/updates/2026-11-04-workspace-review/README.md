# 모바일 업무 공간과 반복 플레이 리뷰

사용자가 올린 트레이드 화면에서는 선택 메뉴가 큰 고정 영역을 차지하고 선수 목록이 아래로 밀렸다. 같은 틀을 사용하는 영입·코치·기록·시설·설정까지 확인했다. 실물 Safari와 서비스 배포 상태는 아래 검증 한계와 구분한다.

## 화면 수정

- 업무 선택창은 `flex:1`을 제거하고 높이·최소/최대 높이를 모두 44px로 고정한다. 선택창이 하나여도 콘텐츠 패널과 분리한 탐색 행 안에 배치한다. 트레이드 주 메뉴와 세부 모드는 나란히 놓는다.
- 리그 하위 메뉴의 `lseg` 조작도 같은 규칙으로 접는다. 이전에는 이 메뉴만 제외되어 여러 줄을 차지했다.
- 필터를 펼치거나 주소창이 높이를 바꿀 때 DOM을 다시 만들지 않고 패널의 남은 목록 공간을 측정한다. 공간이 부족하면 설명과 필터를 내부 스크롤 영역에 포함한다.
- 국가대표의 소개·유니폼 등은 처음부터 내용 영역에 포함한다. 이미지가 늦게 로드되면서 이미 배치한 표를 밀어내는 경우를 방지한다.
- 낮은 가로 화면에서는 보고 묶음 탐색을 업무 메뉴 옆에, 목록 페이지 버튼을 제목 옆에 놓는다. 경고문도 내용 안에서 읽고, 선수단 메뉴는 한 줄 그리드로 유지한다.

수정 전 검사에서 작은 화면의 FA·외국인·코치·국가대표, 필터 펼침, 낮은 가로 화면의 본문 부족을 확인했다. 기존 검사의 본문 최소 30px 조건만으로는 이런 불편을 찾지 못하므로, 실제 읽을 공간과 펼친 필터까지 검사하도록 추가했다.

## 반복 플레이에서 고친 오류

- 개인 활동에서 선택한 선수·단장을 재렌더 후에도 유지한다. 식사 뒤 면담이 다른 구단 단장으로 바뀌지 않는다.
- 개인 친분은 인물에게 귀속한다. 전임의 친분을 후임이 물려받지 않으며 구단 간 거래 관계는 별도로 유지한다. 기존 저장은 현재 인물에 연결한다.
- 단장 면담은 기존의 우승 도전·전력 정비·재건 전략과 보강 필요·예산·성향을 반영한다. 같은 날 사실이 바뀌면 새 답변을 한다. AI 전략이나 경기 난이도 자체를 개편한 것은 아니다.
- 공동 관전 보고를 Escape·다른 메뉴 이동으로 닫는다. 관전 결과 데이터는 보존한다. 서로 다른 결과 보고는 읽기 위치를 공유하지 않는다.
- 긴 면담은 새 답변까지 스크롤하고, 과거 대화를 읽는 동안 높이만 바뀌면 위치를 유지한다. 낮은 가로 화면도 내용·화제를 각각 스크롤한다.
- 화면 전환 직후 진행 설정 체크가 중복 결정 방지에 막히지 않도록 분리한다. 금전·계약 결정의 보호는 유지한다.

## 시즌 플레이 기록

서로 다른 시드·구단으로 실제 계속 버튼·소식 결정·경기 결과·명단·선수 카드·면담을 조작했다. 드래프트 자동 지명·기본 보상 명단·정원 정리·감독 재계약은 정상 게임 명령으로 처리했다. 날짜 강제 이동이나 오류 상태 삭제는 하지 않았다.

| 화면 | 시드/구단 | 계속 진행 | 경기 결과 묶음 | 다음 해 도착 | 2026 성적 |
| --- | --- | ---: | ---: | --- | --- |
| 휴대폰 | 7 / 6 | 81 | 50 | 2027-01-01 | 7위, 68승 72패 4무 |
| 태블릿 | 21 / 2 | 101 | 60 | 2027-01-01 | 6위, 72승 71패 1무 |
| PC | 3 / 9 | 83 | 50 | 2027-01-05 | 7위, 67승 75패 2무 |

각 조건에서 저장 후 새로 접속하여 날짜 보존도 확인했다. 태블릿은 기본 중단 설정, 휴대폰·PC는 선택 중단 조건을 줄여 비교했다. 스카우트 위임 후 담당 공백이 있더라도 실제 인원 부족이 없으면 불필요한 배치 결정으로 막히지 않았다. 위 플레이는 공통 화면 압축의 마지막 보완 전 결과이며, 최종 배치는 별도의 전체 화면 검사로 검증한다.

요약 원본: [휴대폰](phone-season.json), [태블릿](tablet-season.json), [PC](pc-season.json).

## 검증

- 단위 검사 33개, 정적 검사 3256개 선언, 개인 인맥·교체·상황별 면담 규칙 통과.
- 개인 활동 상대·검색·진행 설정 실제 조작: 휴대폰·태블릿·PC 통과.
- 긴 면담·관전 보고·보고 식별·높이 변화: 1366×768, 768×1024, 390×664, 568×320 통과.
- 기존 상단바 12종 상세/결재와 이동 검사 통과. PC의 이전 상단 홈 탭 선택자는 현재 상단 소식함 버튼으로 바로잡았다.
- 7가지 크기의 전체 메뉴·하위 모드·보고 묶음을 검사했고, 마지막 낮은 가로 보완 뒤에는 390×664와 568×320의 전 경로를 재확인했다. 선수 검색·외국인 설명 펼침·코치 명단에서 실제 터치 스와이프와 전체 페이지로의 스크롤 전파 방지도 통과했다.
- 최종 화면 변경 뒤 휴대폰·태블릿 각각 20회 추가 플레이에서 37회 날짜 진행, 3회 소식 확인, 경기 결과·명단·선수 카드·면담·저장 복귀 통과.
- 소개·이미지와 함께 스크롤하는 긴 표에서도 모바일/PC의 열 제목이 고정되는지 추가 확인했다.
- 전체 검사 실행은 환경 세션 종료로 중단됐다. 규칙 403개 통과 기록을 유지하고 시나리오별 독립 시드로 미완료 15개를 재개하여 기존 규칙 418개 전부 통과했다. 개인 활동·시설·연수·저장, 시작 화면, 계속/날짜 효과, 3경기/관전 선택, 홈, 터치/회전/저장, 선수 카드/읽기/파일, 개인 활동 상대, 긴 면담, 제안 카드, 디자인, 32개 메뉴×4크기 내부 스크롤, PC 높이 검사는 통과했다.
- 전체 업무 공간 검사에서는 PC→568×320 전환 뒤 코치 목록 1건이 실패했다. 첫 레이아웃 뒤 실제 목록 크기가 바뀌는데 재측정되지 않은 것이 원인이었다. `ResizeObserver`로 스크롤 영역의 크기 변화를 감지하고 다음 프레임에서 공간을 확보하도록 수정했다. 해당 전환의 351개 경우와 터치/표 고정 검사를 수정 후 통과했다.
- 재개한 전체 묶음은 능력 반영 검사 단계에서 실행 연결이 다시 종료되어 전체 완료로 보고하지 않는다. 이후 최종 HTML을 재생성하고 수정에 관련된 검사를 별도로 마무리했다.

- 푸시 직전 최종 빌드: 단위/빌드 계약 33개, 정적 선언 3256개, 개인 인맥·면담 규칙(시드 3/7/11/21), 7개 화면 크기의 전체 업무 경로·모드·보고 1252개 조합 및 실제 터치/표 머리글 검사 통과. 면담 규칙의 저장 복원 준비는 기존 전력 조회의 보직 정규화 후 세계 캐시를 비우도록 맞췄다.

- 최종 HTML에서 휴대폰·태블릿 선수 카드/자세히/검색/저장 파일 왕복, 4개 화면 크기의 공동 관전 보고/결과 식별/긴 면담/높이 변화 검사를 재통과했다.

## 화면과 검증 한계

[모바일 제안·매물](mobile-trade.png), [코치](mobile-coach.png), [외국인](mobile-foreign.png), [낮은 가로 선수단](landscape-roster.png).

화면 검사는 Chromium의 터치·뷰포트 모사다. 사용자 스크린샷의 Safari 거대 선택 영역은 같은 모습으로 재현하지 못했으며, 확장 가능한 flex 속성을 제거하고 별도 행·명시적 크기로 제한했다. 실물 iOS 검증 완료로 주장하지 않는다.

Cloudflare 주소의 `/release.json`은 이 환경에서 CONNECT 403으로 차단된다. main 반영과 실서비스 새 배포 확인은 별개다. 서비스 게시판에는 메시지를 보내지 않았다.
