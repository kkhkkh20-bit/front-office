## 3. 프로젝트 규칙 (반드시 지킴)

1. **사용자 구단 = AI 구단.** 같은 상황이면 같은 규칙·같은 판정·같은 정산을 씁니다. 사용자에게만 막고 AI는 통과시키거나, 그 반대가 되면 안 됩니다. 한 경로만 고치지 말고 같은 일을 하는 모든 경로(직접 버튼·위임·AI 월간 처리·연말 처리)가 **공통 함수 하나**를 쓰게 합니다.
2. **메인 난수 순서를 바꾸지 않습니다.** 새 판정에 난수가 필요하면 `withRng(...)`나 `rngHash(...)`를 씁니다. `R()`를 새로 부르거나 기존 `R()` 호출을 없애지 않습니다. 난수 순서를 고정한 검사 `[검수 11-09b]`가 계속 통과해야 합니다.
3. **예전 저장을 고칩니다.** 저장 형태를 바꾸거나 잘못 쌓인 값을 정리해야 하면, 불러올 때 도는 정리 함수(마이그레이션)를 둡니다. 두 번 돌려도 결과가 같아야 하고(멱등), 난수를 쓰지 않습니다.
4. **테스트를 끄거나 지우지 않습니다.** 기존 검사가 깨지면 원인을 찾아 코드를 고치거나, 세계가 바뀌어 준비 단계만 어긋난 경우에 한해 준비만 고칩니다(확인하는 내용은 약하게 하지 않음).
5. **화면 문구는 한국어, 합니다체.** 짧고 사실대로. 버그 수정 자체를 패치 노트에 "고쳤다"로 쓰지 않습니다(바뀐 규칙·동작으로 씁니다). 패치 노트가 필요하면 `src/ui/media/75_patch_notes.js` 맨 위에 `{id:'YYYY-MM-DD-이름', ...}`로 한 줄 추가.
6. **PC는 페이지 전체가 스크롤되면 안 됩니다**(칸 안 스크롤은 됨). 휴대폰 390px에서 가로로 넘치면 안 됩니다.
7. 개인 정보·이메일·모델 이름을 코드·커밋 메시지에 넣지 않습니다.

## 4. 준비와 명령어

```bash
# 의존성(한 번)
npm --prefix tools ci        # 또는 기존 tools/node_modules 링크 사용

# 빌드 (소스 바꾼 뒤 항상)
bash build.sh && bash build.sh --engine-out dist/engine.js

# 정적 점검 (항상 통과해야 함)
node tools/check-static.js

# 규칙 점검: 이름에 들어간 글자로 골라 돌림
ONLY="검수 11-17 #308" node tools/check-logic.js
ONLY="트레이드" node tools/check-logic.js
ONLY="11-09b" node tools/check-logic.js    # 난수 순서 고정 검사(항상)

# 서버(Worker) 코드를 바꿨다면
node --test tools/test/*.test.cjs

# 화면을 바꿨다면(Chromium 필요)
node tools/check-desktop-fit.cjs
# + 관련 tools/check-*.cjs
```

- 소스는 `src/` 아래 파일을 고칩니다. `index.html`은 빌드 결과물이라 **직접 고치지 않고**, 빌드 후 생성된 것을 커밋에 함께 넣습니다.
- 파일 구성: `src/modules.json` 순서대로 이어 붙여 하나의 전역 스크립트가 됩니다(새 파일을 만들면 여기에 등록). `src/core/*.mjs`는 서버와 같이 쓰는 모듈입니다.

## 5. 항목마다 할 일

1. **먼저 재현합니다.** 고치기 전 코드에서 실패하는 검사를 `tools/check-logic.js`에 `T('[검수 11-17 #번호] 한 줄 설명', ()=>{ ... })` 형태로 추가해, 실패하는 것을 확인합니다.
2. 원인을 찾아 고칩니다(위 규칙 1~3).
3. 같은 검사가 통과하는 것을 확인합니다. 사용자 구단과 AI 구단 양쪽을 모두 확인하는 검사면 더 좋습니다.
4. 재현이 안 되면 고치지 말고 "재현 안 됨 + 시도한 조건"을 보고합니다.
