## 공통 계약과 기록 호환

새 타석 의미는 PBP의 추가 `row[18]` 객체에 저장한다. 번트 네 종류, FC·실책, 실제 야수·타구 종류, 아웃 목적지·주자, 타수 여부를 포함한다. `gamePA(row)`가 엔진·해설·결과 칩·대회 기록에 같은 의미를 제공한다. 기존 `row[17]` 타구 문자열, `row[16]` 번트 포스아웃 주자, 마지막 투구의 번트 흔적은 구형 폴백으로 해석한다. 공별 기록을 꺼도 새 의미는 남는다. 목적지가 없는 구형 FC에는 특정 송구 목적지를 만들어 넣지 않는다.

구형 BB/HBP 합계는 원자료 없이 분리할 수 없다. 기존 12칸의 위치·숫자를 유지하고 HBP를 뒤에 추가하며, 구형 누적과 새 기록이 섞인 칸의 미분리 표식을 보존한다. 이런 기간의 정확한 WHIP와 WHIP 타이틀 판정은 보류한다. 구형 TSV 박스는 숫자를 바꾸지 않고 헤더를 `BB/HBP`로 표시한다. 옛 완료 리그의 plain L.pit에 hbp가 없는 경우도 마감 시 미분리로 전달한다. CSV 조회는 기존 v2 상태를 읽고 v1은 분리된 복사본에서만 정규화하여 저장·난수를 변경하지 않는다. 원자료 없는 과거 타이틀·MVP·역전 횟수를 추측해 다시 쓰지 않는다.

투수 자격 수정은 합법적 교체 후보가 없는 경우와 경기를 시작할 투수 자체가 없는 경우를 구분한다. 전자는 현재 합법적 투수의 비상 계속 투구를 기록하고, 후자는 일일 진행의 재처리 대기 경로를 따른다. 명단 밖 선수나 당일 사용 선수를 조용히 투입하지 않는다.

## 재현·회귀 검증

신규 통합 회귀는 고유 52건이다: 투수 자격 12, 자책점·타석 의미 9, 해설·장면 6, 패널·순위 9, 대회·래더 9, 독립 자격·자책점 교차 4, 저장 스키마 교차 3. 담당별 private baseline은 수정 전 캡처했으며 원래 보고 사례의 의도한 실패를 확인했다. 최초 통합 세 묶음은 17건 통과, 18건 중 재현 fixture 준비 1건 실패, 17건 통과였다. #765 fixture의 동일 조건 탐색 한도를 100에서 1000으로 늘린 뒤 해당 재현은 통과했다. 판정 조건은 바꾸지 않았다. 최종 두 번째 묶음도 18건 모두 통과했으며, 세 묶음 합계 **고유 52건 모두 통과**를 확인했다.

대회·래더 자체 9건과 최신 저장 스키마 교차 3건은 각각 통과했다. 스키마 교차는 실제 타석 저장→JSON 복원, 옛 완료 리그 최종 누적→CSV, 여러 시즌의 구형·신형 배열을 검증한다. 기존 래더 누적·구형 저장 마이그레이션도 각각 다시 통과했다. 담당별 관련 기존 회귀에는 승계주자·실책 재구성, 홈런·번트FC 자책, 선발 운용·엔트리, 중계·좌우 상대·사구, 래더 시리즈·대회 진행 및 Worker 점검이 포함된다.

정상 투수 운용의 수정 전후 고정 경기는 같은 투수 ID·아웃·투구 수와 최종 주 난수를 유지했다. 자책점 검증은 수정 전 private engine에서 얻은 동일 G 전체 해시를 기준으로 한다. 고정 seed·고정 벽시계·lite 세계 생성으로 이름·생성 경과 시간까지 맞췄으며 정상 경기 3개는 결과·박스·로그·주 난수 전체 해시가 같다. 실책 경기 2개는 의도적으로 수정된 ER 필드만 제외한 경기·난수가 같다. 초기의 일반 fresh는 생성 중 사전 경기 ER 수정으로 세계가 달라지는 문제가 있어 이 비교에 적합한 동일 세계 fixture로 교체했다. 실제 비교 단정은 완화하지 않았다. 가상 이닝은 저장된 주루 판단을 재사용하고 추가 주루 난수를 뽑지 않는다.
