## 공통 규칙과 예전 저장

거래 평가는 `evalTrade(tid,give,get,cash,pk,actorTid,relOv)`의 명시적 거래 주체를 지원한다. 관심선수·재영입 제외·지명권 매집·독주 견제·반복 거래 기록도 해당 주체 기준으로 계산한다. AI 거래는 실제 전체 묶음을 양쪽에서 평가하며 반대편 평가에는 현금과 지명권 방향을 뒤집는다. 기존 맞트레이드·창단/운영 방향 보강은 후보를 고르는 역할을 유지하고 실제 이동은 공통 최종 판정을 통과해야 한다. 명시한 친밀도에만 음수 요구치를 막던 AI 전용 분기도 제거하고, 같은 친밀도에는 같은 요구치와 공통 최종 최소 마진을 적용한다. 추천과 역제안은 실제 제출의 자격 검사를 공유하여 미리 통과했다고 보여 준 안이 제출에서 규정으로 막히는 차이를 줄인다.

평가·추천 검증은 조회다. 견제 통계는 실제 협상 결과에만 기록한다. 옛 선수의 다재다능·수비 숙련 기본값은 같은 결정적 값으로 읽고, 실제 전환·훈련·정착 때 `pexpEnsure`로 저장한다. 저장 참조가 바뀌거나 당일 실제 라인업·계약 상태가 바뀌면 주전·FA 거래 잠금도 현재 상태를 따른다.

예전 매물 정리는 `aiBlockDates`가 맡고 `migrateDraft`에서 한 번 호출한다. 날짜 없는 옛 마감 매물은 가장 최근 7월 24일로 연결하며, 원인이 있는 날짜 미상 매물은 불러온 날부터 유효 기간을 제한한다. 42일 지난 매물은 부상 여부와 무관하게 제거한다. 등록일 0을 결측값으로 보지 않으며 반복 정리는 멱등이고 난수를 사용하지 않는다. 옵션·거래 기록 형태를 바꾸는 마이그레이션은 없다. **#786으로 이미 잘못 덮어쓴 옵션 조건은 원래 합의 종류를 입증할 자료가 없으면 추측해 복원하지 않는다.** 기준이 없는 옛 계약 입력은 기존 보직 기본값 호환을 유지한다.

목표 지원율은 `goalSupportFix`가 기존 확정 장부를 기준으로 복원한다. 새 목표 생성 때도 기본 지원율을 명시적으로 확정하여 첫 현금 역제안·자금 조회가 저장을 바꾸지 않는다. 실제 불러오기와 반복 불러오기·첫 자금 조회의 전체 저장 및 난수 불변을 검사했다. 기존 #487 예산 호환 계산과 검증도 유지했다.

## 검사 준비 조정과 규칙 변경

#804는 보고된 규칙인 '두 번째 1라운드부터 40%씩'을 적용한다. 기존 `#314` 검사의 1.00/1.40은 1.40/1.80으로, 두 장 중 한 장을 바꾸는 검사의 최종 두 장 배율은 1.40으로 갱신했다. 같은 거래로 내주는 지명권을 빼는 단정과 2라운드 면제·복수 수령 순서·입력 중복 단정은 유지한다. 이는 이번 명시 규칙의 기대값 변경이다.

기존 보강 할인 검사의 준비에서는 실제 나가는 슬롯을 사용하고 보조 포지션이 없는 사례에 `pexp:{}`를 명시한다. 주 포지션만 막아 놓고 실제 가능한 보조 자리로 보강되는 선수를 '보강 불가'로 가정하던 준비를 맞춘 것이다. 보강일 때 할인하고 실제 같은 자리를 대체할 때 할인하지 않는 검증 내용은 유지한다. 포지션 검사의 준비에서 getter를 setter처럼 사용하던 부분은 `pexpEnsure`로 실제 숙련값을 저장한 뒤 검사하도록 바꿨다. 읽기와 판정 기대값은 유지했다. 기존 테스트를 삭제하거나 비활성화하지 않는다.

## 독립 교차 검증

고유 4건을 담당 구현과 별도로 재현했다. 같은 날 JSON 복원 세계에서 실제 depth·faUpcoming과 거래 주전·잠금이 함께 달라지는지, 실제 추천 유효성→반복 평가가 영구 장부·난수를 바꾸는지, JSON 복원한 역제안의 실제 제출이 독주 금지에서 선수·현금·지명권을 보존하는지를 확인했다. 첫 세 검사는 실제 로스터와 실제 평가·추천·제출 함수에 돈·견제 조건만 고정했다.

네 번째는 선수 가치나 판정 함수를 바꾸지 않았다. lite 세계의 정상 능력치 로스터에 유효 매물 표시를 설정하고 실제 AI 거래를 실행했다. 수정 전에는 확정된 전체 묶음에서 B 구단의 실제 공통 평가가 gain -11.057, need -0.342로 거절인데도 거래가 성사됐다. 수정 후 같은 탐색 조건에서 실제 성사본을 거래 직전 JSON으로 되돌려 양쪽 모두 수락함을 확인했다. 거래가 한 건도 없으면 통과하지 않는 검사다. 평가 재검증은 G JSON과 주 난수도 보존했다. 명시적 관계 요구치의 AI 전용 제한 제거와 순수 수비 getter까지 포함한 최신 소스에서 네 검사 모두 다시 통과했다.
