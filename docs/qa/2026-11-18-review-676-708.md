## 저장 확정과 호환

새 IndexedDB 저장은 판별 가능한 개별 본문 키와 확정 기록을 사용한다. 본문·확정 기록 검증이 끝나야 목록과 활성 슬롯을 공개한다. 실패한 쓰기는 자신이 차지한 판의 목록만 되돌리며, 늦게 끝난 이전 탭이 더 새 쓰기를 취소하거나 덮지 못한다. 같은 시각·같은 숫자 판번호가 발생하는 강제 조건도 쓰기 식별자로 구별한다.

다른 탭의 진행 중 저장, 쓰기 뒤 확정 기록 실패, 목록 공개 실패, 중도 종료, 일부 삭제 실패, 목록 유실 뒤 복구, 삭제한 과거 판의 재등장 방지를 검사했다. 읽기 실패 때 이전 캐시를 새 판으로 위장하지 않는다. 삭제 실패 때 현재 확정 본문과 확정 기록을 복원한다.

목록 차지를 위한 일회성 공간이 필요한 경우 게임이 미리 확보한 2048자 예약 공간만 해제하고 다시 쓴다. 실제 저장 데이터를 먼저 지워 공간을 만들지 않는다. 같은 공간 채움 검사는 기준 커밋에서도 통과하는 것을 확인했고, 새 확정 형식 때문에 생겼던 공간 부족 회귀를 이 예약 공간으로 해결했다.

기존 숫자 IndexedDB 슬롯과 저장 형식을 지원한다. `SaveStore.big.keys()`는 선택적인 추가 인터페이스이며 기본 웹 저장소는 새 키를 검색한다. 오래된 외부 어댑터는 숫자 슬롯 읽기를 유지한다. 새 필드는 저장 위치·확정·쓰기 식별 정보이며 게임 세계 시드나 미래 난수를 저장하지 않는다.
