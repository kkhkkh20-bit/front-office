# 구단 소유권·경영 정책 UI — 2026-11-10

## 구현

`ownershipCard(tid)`는 엔진의 순수 `ownershipView(tid)`를 읽고, `ownershipMarkup`이 반환값을 표시한다. 회사와 구단주 사람을 별도 항목으로 보여 주며, 구단명·엠블럼·유니폼을 변경하지 않는다. UI가 소유권 데이터나 이벤트를 생성하지 않는다.

- PC 구단 개요의 기본 정보 칸에는 현재 모기업·구단주·경영 단계·방침·지원 한도 요약과 이력 화면 바로가기를 넣었다.
- 모바일 구단 개요와 타구단 공개 개요에는 같은 API의 상세 카드와 접어서 읽는 이력을 넣었다.
- 구단주·목표 화면에도 같은 카드를 표시한다. PC는 기존 피드백 카드의 내부 스크롤 영역을 사용하고 기존 그리드 구성을 늘리지 않았다. 모바일은 새 소유권 카드를 먼저 읽는다.
- 공개 프로필의 기본 정보와 운영진 탭도 API의 현재 구단주를 우선한다. 기존 인물과 `ownerId`가 다르면 그 인물의 나이·경력을 새 구단주에게 붙이지 않는다.

`supportPct`는 실제 적자 보전 지급 비율이 아니라 **기본 지원 한도 대비 %**로 표시한다. 다른 `nextSupportPct`가 있으면 별도 줄에 `effectiveYear` 회계연도부터 적용된다고 표시한다. 투자사 운영의 지원 0은 모기업 지원 없음으로 표시한다. 한도 금액이나 다른 구단 예산을 UI에서 추정하지 않는다.

이력은 UI 사본을 최신순으로 정렬하며 원본 배열을 바꾸지 않는다. 실제 `title`/`text`를 그대로 표시하고 `from`/`to` 객체의 당시 모기업·구단주 이름을 함께 보여 준다. 과거 사건을 현재 구단주의 이름으로 다시 만들지 않는다. 옛 기록의 문자열 스냅숏과 `d:null`도 처리하며, 날짜가 없으면 일자 기록 없음으로 표시한다. 실제 자본 투입 객체는 금액·출처·투입 전후 구단 현금을 별도로 표시한다. 스냅숏에 다음 지원 정책과 적용 회계연도가 남으면 그 기록도 표시한다.

## 이미 합의한 시즌 목표

소유주가 교체돼 현재 `team.owner`가 바뀌어도 유효한 올해 `G.goals.owner`가 있으면 `ownerView`/`ownerDash`의 목표 설명과 평가 가중치는 합의한 성향을 사용한다. 현재 정책과 다를 때 다음 안내를 표시한다.

> 현 구단주 방침은 다음 시즌 목표부터 적용됩니다. 이번 시즌에는 합의한 목표·평가 기준을 유지합니다.

구단주 지원 요청 설명은 실제 현 구단주의 성향을 별도로 사용한다. 현재 방침과 이미 합의한 평가 기준을 혼동하지 않도록 제목도 구분했다.

## 실제 API·전이 검증

검사 도구는 `tools/check-ownership-ui.cjs`다. `build({write:false})` 결과를 `/tmp/ownership-working.html`에만 만들며 배포 HTML과 엔진은 쓰지 않는다.

```sh
node tools/check-ownership-ui.cjs
```

내 구단과 AI 구단 각각에 실제 `ownershipStart`와 `ownershipDaily`를 호출해 다음 10개 흐름을 검증한다. 자연 발생 확률 검사가 아니라 공식 엔진 조건을 갖춘 UI 통합 fixture다.

- 구단주 승계: 사람의 ID 변경, 모기업 ID 유지.
- 정상 인수와 위기 후 매각: 사람·모기업 ID 변경.
- 기존 모기업 회복: 구단주 유지, 실제 자본 투입 이력.
- 리그 임시 지원: 구단주 유지, 매각 계속 단계, 실제 임시 자금 이력.

각 전이 뒤 UI 조회의 `G` JSON 불변과 RNG 미사용, 현재 인물·과거 스냅숏 동시 보존, 객체형 자본 투입 표시를 확인한다. 승계 전 합의한 목표 성향이 남고, 실제 화면의 평가 가중치도 기존 성향의 값인지 검사한다.

초기화 전의 저장 상태에서도 `ownershipView`와 공통 UI를 조회해 `G` 불변·RNG 0을 확인한다. 기존 `G.rescues`의 과거 인물 이름과 날짜 미상 정보도 그대로 표시한다. RNG는 페이지 로드 전에 계수기를 설치하므로 엔진이 미리 캡처한 `R` 호출도 검출한다.

## 브라우저 검증

1366×768, 390×844, 768×844에서 실제 승계된 우리 구단주 화면과 리그 지원 중인 타구단 공개 프로필을 열고, 이력 접기/펼치기·자본 투입·단계·회사와 사람·지원 적용 연도를 확인한다. 공개 프로필 전체 조회의 `G` 불변, 사용자 ID 유지, 우리 구단 예산 칩 미노출도 검사한다.

별도로 확정 API 반환값 형태의 순수 렌더링 fixture를 사용해 긴 회사명, 82건 이력의 내부 스크롤, 날짜 없는 옛 기록, 지원 한도 현재 100%와 다음 65%/2027 회계연도 구분을 확인한다. 이 단계는 저장 상태를 추가하거나 API 함수를 가로채지 않고 렌더러 인자만 사용한다. 실제 엔진 전이 검사와 구분해 결과를 기록한다.

증거는 `/tmp/ownership-ui/results.json`, `/tmp/ownership-ui-final.log`와 화면 폭별 `-own-owner.png`, `-own-history.png`, `-public-api.png`, `-public-history.png`, `-history-future-policy.png`다. PC 구단주 화면과 390px 공개 프로필 스크린샷도 열어 배치를 확인했다.
