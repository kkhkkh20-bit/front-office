## 동작과 근거

#105 저장 스냅샷의 분포는 시즌 집계와 최근 250타구로 제한된 기존 자료를 그대로 깊은 복사한다. 박스스코어에서 방향별 홈런이나 상대 손별 집계를 정확히 역산할 수 없으므로 단순히 총 홈런을 빼는 처리는 하지 않는다. 화면을 그릴 때만 경기 전 사본을 사용하며 실제 선수의 확정된 경기 기록은 유지한다. 전년도 분포가 경기 전 자료였다면 그 연도를 그대로 표시한다.

#111 안타 다음 경기가 희생플라이만인 경우 실시간·로그 재생 모두 `streak=0/hitless=1`이다. 볼넷·사구·희생번트만 있으면 기존 연속 안타를 유지한다. 구형 로그에 SF 칸이 없으면 남아 있는 해당 날짜 박스의 선수 ID·PA·AB·H가 일치하는 실제 자료가 한 건일 때만 SF를 보완한다. 박스도 없는 과거 로그에 SF를 추정해서 넣지 않는다.

#112 새 공별 기록은 기존 저장된 측정 모형의 공 배열을 그대로 읽는다. 공별 자료 없는 옛 타석은 Fisher–Yates 기반 공통 생성기로 같은 결과에 맞는 순서를 재현하되 `legacy:true/v:null/구종 미기록`으로 구분한다. 현재 선수 능력, 현재 구속, 현재 구종표와 무관하며 조회는 게임 난수를 소비하지 않는다. 경기 박스의 손잡이 기록을 먼저 사용하고, 해당 필드가 보관 선수 자료에 남아 있는 경우 그 근거만 보완한다. 근거 없는 구속을 임의 숫자로 표시하지 않는다.

출처는 ‘투구 재현’, 공 설명은 ‘구종 미기록 / 구속 미기록 / 추정 재현’으로 표시한다. 좌표·카운트는 재생 연출의 추정이며 당시 측정값이 아니다. null 구속은 DOM이나 3D 전광판에 숫자로 전달하지 않는다. 3D 투구 시간은 기존 유한한 기본 속도 하한을 사용하며 좌표는 수치로 유지된다.

## 통합 피치 UI 검사 기대 정정

기존 `tools/check-pitches.cjs`의 ‘우측 하단 카운트’ 조건은 모든 폭에서 `#cs-bso`가 `.md-pitch-dock` 안에 있다고 가정했다. `c372fd88:index.html`을 별도 추출한 원본 HTML에서도 동일하게 390px 검사만 실패했다. 해당 baseline CSS와 현재 CSS 모두 이미 모바일 카운트 패널을 `#cs-stage > .md-count-panel`로 옮기므로 이번 제품 변경의 회귀가 아니다.

제품 소스는 바꾸지 않고 검사에 `PITCHES_HTML` 옵션을 추가했다. 카운트가 실제 `.md-count-panel` 안에서 보이는지 공통 검사하고, 모바일은 구장 안, PC는 기존 투구판 하단 안에 있는지 확인한다. 정정 후 baseline과 root가 빌드한 현재 `index.html` 양쪽에서 기존 전체 피치 UI 검사가 exit 0으로 통과했다. 검사 폭은 기존 1280/1366/1920/390 그대로다.
