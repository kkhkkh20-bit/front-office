# 전체 구단 영구결번 바로 보기

기준 main: `0c9a21a5`.

## 확인한 내용

최신 기준 빌드에서 실제 모바일 버튼 클릭은 리그 역사 > 우승 트로피로 이동했고, `switchTeam` 이후 이전 구단의 결번도 `G.orgT`에 보존되어 있었다. 따라서 사용자 제보의 기록 삭제나 빈 역사 화면 자체를 이 빌드에서 재현했다고 주장하지 않는다. 사용자 저장 파일과 서비스 배포 상태는 확인하지 않았다.

다만 모바일 첫 화면에 결번이 없는 현재 구단의 큰 빈 트로피 진열장이 나오고, 이전 구단의 결번은 아래쪽 카드에 묻혀 있었다. 이 조회 경로를 개선했다.

## 변경

- OB·레전드의 전체 구단 영구결번 버튼은 전용 목록으로 직접 이동한다.
- 리그 > 역사에 영구결번 탭을 추가했다.
- 기록이 있는 구단부터 표시하고 전체 구단 수·총 인원을 항상 표시한다. 결번이 없는 구단도 명시적으로 안내한다.
- 트로피 공간 없이 번호·선수명·지정 연도를 보여 준다. 목록은 패널 내부에서 스크롤한다.
- 해당 이동을 탐색 동작으로 분류해 연속 터치 보호에 불필요하게 막히지 않도록 했다.
- 엔진의 결번 저장·이직 로직은 변경하지 않았다. 이미 소실된 기록을 복원하는 변경은 아니다.

## 검증

`node tools/check-retired-navigation.cjs`: 390×664, 768×1024, 1366×768 모두 통과. 결번 후보 상태를 준비한 뒤 실제 `retireNumber` → `switchTeam` 실행, 화면의 전체 보기 버튼 클릭, 역사 탭 왕복, 저장 → 새로고침 → 이어하기, 원래 구단 복귀를 확인했다. 10개 구단 표시·이전 구단 첫 화면 노출·중복 없음·전체 결번 0명 안내·가로 넘침 및 브라우저 예외 없음도 검사했다. 후보 생성과 이직 결정 자체는 자연 시즌 플레이가 아닌 준비 호출이다.

기존 커뮤니티 UI 검사도 같은 세 화면 크기에서 통과했다. 기존 모듈·빌드 검사 34개와 정적 검사 통과. 새 조회 검사는 `tools/check.sh`에 포함했다. 증거 이미지·실행 결과를 이 폴더에 보관한다.

## 안내문

전체 구단 영구결번을 더 쉽게 확인할 수 있도록 전용 목록을 추가했습니다. 이제 OB·레전드의 ‘전체 구단 영구결번 보기’를 누르면 목록이 바로 열리며, 리그 > 역사 > 영구결번에서도 확인할 수 있습니다. 결번이 있는 구단부터 표시하고, 이직 전 구단 기록의 저장·불러오기와 복귀 후 표시도 확인했습니다. 앞서 과거 기록 때문이라고 단정해 안내드린 점 죄송합니다.
