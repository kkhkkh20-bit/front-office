자체 추가 발견: 제작비가 현금에서 즉시 차감되지 않고 `G.spend.fan`에 쌓이므로 같은 독립구단 현금을 여러 제작에 재사용할 수 있었다. 승인 시 이미 예약된 팬 마케팅 비용을 가용 현금에서 제외했다. 현금 500에서 첫 1만 벌 제작 후 추가 제작 거절을 확인했다. 결번 지정 시에도 새 기록에 `pid`와 가능한 `ob` ID를 저장하여 앞으로 이름만 있는 모호한 기록이 늘지 않게 했다.

검사 명령:

```sh
node tools/check-audit-family.cjs --baseline
node tools/check-audit-family.cjs
```

두 명령 모두 통과. baseline 모드는 메모리 빌드의 담당 소스와 이직 장부 소스만 `git show 01ffefcf:<file>`로 대체하여 9개 오류가 모두 존재함을 확인한다. 기본 모드는 9개 수정 확인과 ID 우선/옛 저장 호환/다른 선수 및 구단의 허락 제한/제작비 예약/동일 선수 120일 제한 검사를 통과했다. 수요 검사에서는 해당 정규 난수 한 곳만 고정한다. `build({write:false})`로 엔진을 만들었고 dist/index 생성이나 장기 시뮬레이션은 하지 않았다.

한계: 이 검사는 목표 엔진 경로의 고정 상태 검사다. 이미 과거에 제거된 아버지 데이터 자체를 복원하지는 않는다. ID가 원래 없던 옛 결번 기록은 과거 저장 호환을 위해 이름 기준으로 허용한다.
