# 레거시 독립 감사 (#1~11)

기준: 현재 main `01ffefcf`의 소스를 확인하고 작업 브랜치의 현재 소스로 재현·회귀 검사했습니다. 입력 보고서의 `8b4b902` 설명은 단서로만 사용했습니다.

실행:

```sh
node tools/check-audit-legacy.cjs
```

검사는 `tools/build.cjs`의 `build({write:false}).engine`을 사용합니다. `dist`와 `index.html`을 읽거나 쓰지 않으며, 1,077개 전체 검사와 장기 시뮬은 실행하지 않았습니다. 새 게임을 한 번 만들고 분기별 저장 상태를 복원했습니다. 희귀 장기 임기는 검사 상태로 구성했고, 결산·이직·세대교체는 실제 엔진 함수를 실행했습니다.

| 번호 | 판정 | 확인 및 수정 |
| --- | --- | --- |
| 1 | 재현 경로 확인 → 수정 | `legRec()`가 화면 조회만으로 `G.gmRec`를 생성했습니다. 이제 읽기용 소급 기록은 비저장으로 계산하고 결산 직전에 명시 초기화합니다. 조회 유무를 나눠 실제 `settlement()`를 실행해 부임 시점 50승40패, 최종 90승54패의 차이인 **40승14패**가 두 경우 모두 남는지 검사했습니다. |
| 2 | 재현 경로 확인 → 수정 | 결산 전 이직은 새 단장의 `psDone` 때문에 기록을 건너뛰면서 전임 정보도 잃었습니다. `switchTeam()` 직전 시즌 종료 당시 전임 신원을 보존하고 결산 시 그 사람에게 귀속합니다. 실제 이직→결산에서 전임 AI 단장에게 87승57패와 우승이 남고 새 단장에게 붙지 않는지 검사했습니다. |
| 3 | 재현 경로 확인 → 수정 | 제안에 구단·인물 검증이 없었습니다. 제안의 `tid`와 현재 구단이 다르면 거절하고 답변 데이터도 변경하지 않습니다. |
| 4 | 재현 경로 확인 → 수정 | 제안에 `legMeK()`와 이름을 저장하고 현재 계보 인물과 다르면 거절합니다. 실제 `gmSucceed()` 후 전임 제안을 수락할 수 없는지 검사했습니다. 인물 식별자가 없는 옛 미결 제안도 안전하게 거절합니다. |
| 5 | 재현 경로 확인 → 수정 | 제안 판정에 독립구단을 제외합니다. 같은 15시즌·신뢰90 상태에서 독립구단은 제안하지 않고, 모기업 구단은 제안하는지 검사했습니다. |
| 6 | 문구 오류 → 수정 | 수치 기준은 원래 `>=15`였습니다. 화면을 ‘15시즌 이상 연속해서’로 일치시켰습니다. |
| 7 | 재현 경로 확인 → 수정 | `myCClose()`에서 임기 종료일을 남기고 닫힌 임기에 새 시즌을 합치지 않습니다. 실제 이직→다른 구단 퇴임→같은 해 31일 후 복귀를 실행해 기존14시즌과 새1시즌이 분리되고 사장 제안이 오지 않는지 검사했습니다. |
| 8 | 재현 경로 확인 → 수정 | `legCur()`가 사람·구단만 확인했습니다. 닫힌 임기는 현재 임기로 판정하지 않고, 옛 저장에서도 같은 사람·구단의 가장 최근 임기를 확인합니다. 두 번째 임기만 재임 중인지 검사했습니다. |
| 9 | 순위 설명과 계산 불일치 → 수정 | 진열 목록은 겹치는 구간을 줄여 보여 주는 기존 설계를 유지합니다. 개인 순위는 문구대로 모든 유효한 연속5년 구간과 비교합니다. 겹치는 상위3구간이 있는 상태에서 개인4위가 되는지 검사했습니다. |
| 10 | 재현 경로 확인 → 수정 | `archPlayer()`가 프랜차이즈 표식을 보관하지 않았고 `lgStars()`도 보관 기록에서 해당 표식을 읽지 않았습니다. 아카이브에 `fr`을 보존하고 읽습니다. 수상 이력이 없는 선수를 실제 보관→현역 명단에서 제거한 뒤에도 배출 스타로 집계하는지 검사했습니다. |
| 11 | 재현 경로 확인 → 수정 | 보호 조건 때문에 제거 후보가 없으면 240행을 넘겼습니다. 최근·현역에 가까운 기록과 내 계보를 우선순위로 보존하되 최종적으로 240행을 지키도록 변경했습니다. 계보 기록만 260행인 상태를 검사했습니다. |

## 추가 발견

한국시리즈 종료 후 결산 전에 **실제 단장 세대교체**가 일어나도 전임의 시즌 기록이 사라질 수 있는 경로를 함께 확인했습니다. `myCClose()`에서 종료 당시 개인 신원을 보존해 결산 시 전임에게 승패·우승을 귀속합니다. 새 단장에게 그 시즌이 붙지 않는 회귀 검사를 추가했습니다.

## 한계와 보존 정책

- 이번 변경은 확인된 귀속 경로를 고칩니다. 과거 저장에 이미 잘못 합쳐진 승패나 소실된 프랜차이즈 표식을 추정으로 되돌리지는 않습니다.
- 예전 기능 설명처럼 AI 단장의 과거 임기 전체를 경기 단위로 재구성하지는 않습니다. 조회에서 세이브·난수·경기 상태를 변경하지 않는 것을 우선 검증했습니다.
- 240행 상한은 보호 기록도 포함한 실제 상한입니다. 장기 세이브에서는 우선순위가 낮은 오래된 임기가 제거될 수 있습니다.
- 변경 파일은 `src/engine/career/90_legacy.js`, `src/ui/career/64b_legacy.js`, 전용 검사와 이 문서뿐입니다. 빌드·커밋·푸시는 루트 담당입니다.
