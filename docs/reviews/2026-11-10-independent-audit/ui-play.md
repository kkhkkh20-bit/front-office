최종 결과는 세 화면 폭에서 각각 6/6, 합계 18/18 흐름 통과다. 현재 확정한 제품 UI 오류는 없다. 조사한 화면에서 문서 가로 넘침은 0px이며 모든 화면의 `pageerror`는 0건이었다. 계약 체결, 실제 방출, 장기 위임 동작, 시즌 경기, 인터뷰/기자 이벤트 생성은 이 조사 범위에서 검증하지 않았다. 따라서 이 결과는 해당 기능 전체에 결함이 없다는 의미가 아니다.

## 실제 플레이와 테스트 준비의 구분

- 새 게임은 `newGame`, `fdStart`, `hireMgr` 등을 평가 호출하지 않고 처음 화면에서 실제 버튼을 눌러 시작했다. 구단은 매 실행 새 세계의 첫 구단을 선택하므로 구단 이름과 소식 ID는 달라질 수 있다.
- 소식함·선수 상세·선수단 정리·방출 결재 취소는 화면 버튼과 Esc로 조작했다. 결재를 취소한 뒤 로스터가 그대로인지를 실제 게임 상태에서 읽었다.
- 계약은 새 게임의 국내 선수 중 `canExtend` 선수를 읽어서 `A.ngtOpen('ext:'+id)`로 협상 화면을 여는 준비만 했다. 계약 입력·뒤로/닫기는 UI로 조작했다. 날짜·연봉·소속·계약조건을 fixture로 변조하지 않았다. 정규 계약 메뉴에서 해당 선수 버튼까지 찾아 들어가는 사용자 경로는 검증하지 않았다.
- PC 위임 화면은 Ctrl+J로 열었다. 모바일·태블릿에서는 `A.go('cfg:auth')`로 진입한 뒤 실제 `넘기기` 버튼을 클릭했다. 모바일 전체 메뉴에서 권한 화면까지의 탐색은 검증하지 않았다.
- 저장은 Ctrl+S, 복원은 실제 새로고침 후 처음 화면의 `이어하기` 버튼으로 수행했다. 원래 게임 상태와 복원한 상태를 비교했다.

## 증거와 재현

실행 도구: `tools/check-audit-ui-play.cjs`. 세 화면을 기본으로 실행하며 `AUDIT_WIDTH=768`로 태블릿만 실행할 수 있다. 기본 입력은 현재 `index.html`이며 `AUDIT_HTML`로 고정 baseline 파일을 지정할 수 있다. `AUDIT_OUT`으로 증거 출력 디렉터리를 분리할 수 있다.

```sh
git show 01ffefcf:index.html > /tmp/independent-ui-baseline.html
AUDIT_HTML=/tmp/independent-ui-baseline.html node tools/check-audit-ui-play.cjs
```

머신 판독 결과와 실행 로그는 `/tmp/independent-ui-audit/results.json`, `/tmp/independent-ui-audit/run.log`에 있다. 태블릿 최종 재검 원본은 `results-768.json`, `tablet-run.log`이며 합산 결과에 반영했다. 각 화면 폭별 스크린샷:

- `<폭>-newgame-inbox.png`, `<폭>-mail-detail.png`, `<폭>-manager.png`, `<폭>-manager-back.png`
- `<폭>-player.png`, `<폭>-player-back.png`
- `<폭>-release-confirm.png`, `<폭>-trim-back.png`
- `<폭>-contract-input.png`, `<폭>-delegated.png`, `<폭>-restored.png`

PC 방출 결재와 모바일 소식함·계약 입력 화면은 이미지도 열어 내용과 배치를 확인했다.

초기 자동화 실패는 제품 오류로 계산하지 않았다. 구단 카드의 중앙은 `자세히`, 정리 카드 중앙은 별점 도움말에 닿을 수 있으므로 실제 선택 버튼/카드 상단을 클릭하도록 수정했다. 모바일 계약 화면의 종료는 PC 모달의 닫기 대신 전체 페이지의 `뒤로`를 사용했다. 복원 버튼의 실제 action 이름은 `tsCont`다. 초기 실행의 `*-failed.png`는 이 셀렉터 탐색 흔적이며 재현된 제품 오류 증거가 아니다.

최종 수정 엔진과 UI의 통합 결과는 이 고정 baseline 조사와 별도로 검증해야 한다.
