# 전 구단 기록 동등성·정확성 독립 검수

기준 소스: `69f146b9`에서 시작한 작업 트리. 대상은 구단별 시즌·통산 기여, 같은 해 여러 구단에서 뛴 선수, 은퇴 보관, 수상, 저장·이직 전후 조회, 정규시즌과 포스트시즌 분리다. 검수자는 생산 코드를 수정하지 않았으며 발견한 결함은 해당 파일 담당자에게 전달했다.

## 검증 방법

`node tools/check-club-records.cjs`는 `tools/build.cjs`의 `build({root,write:false}).engine`으로 현재 소스를 메모리에서 실행한다. 배포 빌드, `dist`, `index.html`, Git 커밋·푸시는 만들지 않는다. 실제 새 게임·창단 드래프트 종료·감독 선임으로 준비하고 검사마다 그 저장 상태를 복원한다. UI 집계는 실제 `04_league_helpers.js`의 `playerRowsT`, `teamStats`도 실행한다.

아래 테스트 대부분은 명시적인 소규모 기록 fixture다. 장기 자연 플레이 결과로 주장하지 않는다. 정규/PS 분리 검사는 실제 `simGame()`과 `applyGame()`을 각각 한 번씩 실행한다. 구단 이동 검사는 실제 `switchTeam()`을 호출한다.

## 재현한 결함과 조치

`44_free_agents.js`의 보관 한도는 현·전 사용자 구단에서 뛴 선수, 수상자·일부 유명 선수 등을 보호하고 나머지 AI 선수 기록을 900명으로 제한했다. 초과 시 개별 ID·이름·경력은 지워지고 `G.archRest`의 구단/시즌 합계만 남았다. 따라서 '모든 구단의 모든 역사를 동등하게 남김'과 충돌했다.

기준 소스에서 위 901명 fixture는 `900 !== 901`로 실패했다. 사용자 선수 이동 담당자가 이 삭제 분기를 제거했고 독립 재실행으로 통과를 확인했다. 과거 저장에서 이미 합계로 합쳐진 `archRest`에는 원래 선수 ID·이름·구간이 없으므로 개인 경력을 정확히 복원할 수 없다. 해당 과거 합계는 계속 팀·리그 합계에 포함하며, 개인 기록을 추정 생성하지 않는다.

## 통계를 읽는 기준

- 구단 성적은 `p.team`으로 필터한 통산 수치를 사용하지 않는다. `seasonTotalT(p,y,'1군',tid)` 또는 `playerRowsT(y,tid,true)`로 해당 연도·구단의 기록만 읽는다.
- 은퇴선수는 `archP(G.arch[id])`로 복원해 같은 API를 사용한다. `careerOf(p).byTeam[tid]`는 전 구단 통산 기여를 보존한다. `careerBoard()`는 리그 전체 통산 순위이므로 구단 통산 기여 API가 아니다.
- 시상 표기 소속 `awClub`은 현재 코드에 명시된 '수상 당시 소속' 규칙이다. 성적·시상 자격/팀 성적 가산용 `awTeamOf`는 그해 가장 많이 뛴 구단을 사용한다. 두 목적의 구단 값이 다른 것은 이 명시된 설계에 따른다. 후보 생성 뒤 발표 전 이동은 수상 스냅숏을 바꾸지 않는다.
- `y2`는 실제 생성처가 퓨처스 다년 합계이므로, `careerOf`에 `!y2`가 없다는 사실만으로 1군 중복합산 결함이라고 분류하지 않았다. 허위 1군 `y2` fixture를 만들어 재현했다고 주장하지 않는다.

## 영구결번 기준 점검

기준 소스의 AI 자동 결번은 해당 구단 실제 WAR 60·8시즌·재적 연도 한국시리즈 우승을 요구했다. 사용자 수동 결번 후보는 설정 `retWarT()`에 따라 기본 WAR60·10시즌, 설정 WAR60 미만이면 8시즌이고 우승 필수 조건이 없었다. 이는 같은 구단 공헌을 동등하게 다루려면 통일해야 하는 설계 불일치로 주 작업자에게 보고했다.

주 작업자가 공통 `retNoRule()` / `retNoStats(p,tid)`를 반영했고 아래 네 검사를 추가해 모두 통과했다. 현재 사용자 구단의 최종 지정은 수동, AI 구단은 자동이라는 운영 차이는 유지하며 자격 기준은 같다.

- 기본 설정 실제 WAR60·10시즌을 AI와 사용자 구단에 동일 적용. 우승이 없어도 자격 충족. AI 행에는 적용한 기준과 실제 재적 연도 우승 참고 이력을 저장한다.
- 설정 WAR40일 때 요구 연도 8시즌을 양쪽에 동일 적용.
- 실제 WAR59에 누락 연차 추정이 더해져 레전드 표기 WAR가 60을 넘더라도 양쪽 모두 신규 결번 자격을 주지 않는다.
- 창단 드래프트 게임에서는 `startY` 이후 해당 구단 1군 기록만 쓴다. 창단 이전, 다른 구단, 퓨처스 WAR를 합쳐 기준을 넘기는 판정은 차단한다.

별도 기존 `tools/check-ai-retired-numbers.cjs`의 15개 검사는 옛 WAR60·8시즌·우승 필수 fixture를 현재 공통 조건에 맞게 수정했다. 기본 fixture를 10시즌으로, 미달 연도를 9시즌으로 바꾸고 우승은 자격 조건이 아닌 실제 재적 연도 참고 이력으로 확인한다. 투수·복수 구단·무적 은퇴·야인·복귀·번호 충돌·OB 및 아들 번호 요청 검증도 모두 유지해 **15개 통과**했다.

```sh
node tools/check-club-records.cjs
# 15 club record checks, 0 failed
node tools/check-ai-retired-numbers.cjs
# passed: 15
```

두 도구 모두 현재 소스를 메모리로 컴파일하며 배포 산출물을 기록하지 않는다.

## 범위와 한계

이 검수는 모든 엔진 경로가 완전함을 증명하지 않는다. 중앙 연대기의 영속 보관·선수 및 스태프 이동 이벤트·전 구단 UI 노출은 다른 담당자가 검증한다. 이름만 남은 오래된 레전드 레코드나 이미 지워진 과거 개인 경력에 정확한 새 수치를 덧붙이지 않는다. 자연 플레이 10년 시뮬레이션은 실행하지 않았다.
