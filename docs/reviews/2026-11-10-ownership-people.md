# 구단 소유권 전환: 인물 관계와 미진행 요청

2026-11-10. 구단주·사장 교체의 공통 후처리 `ownershipPeopleChanged(tid, oldBoss, newBoss, {ownerChanged, ceoChanged})`를 `67_cowatch.js`에 구현했다. `oldBoss`와 `newBoss`는 각각 `{own, ceo}`이고, 변경된 인물은 서로 다른 고유 ID를 가진다. 코어가 실제 인물을 교체한 뒤 이 도우미를 한 번 호출한다. 같은 인물 전환을 다시 호출해도 상태를 다시 처리하지 않는다.

## 조사 및 수정

- 개인 인맥 `G.personal.contacts['own:'+tid]`가 구단에만 귀속되어 구단주가 바뀌어도 보고 응답 캐시와 유대를 물려받았다. `personalOwnerContact`가 인물 ID를 확인하고 이전 연락처를 `own-person:<id>`로 보존한다.
- 동석 초대 `cwInv`, 단장 동행 일정 `gmPlan`, 경기 뒤 건의 `cwS`, 성적 지시 `ownOrder`가 실행할 때 현재 구단주·사장을 다시 조회했다. 생성 시 구단·인물 ID를 고정하고 실행 시 다시 검사한다. 교체 시 변경된 역할의 미진행 항목만 불이익 없이 종료한다. 사장만 교체하면 구단주와 맺은 관계·초대·주문은 유지한다.
- 구단주 면담 장면과 `G.ownReq`의 성적·팬 여론 주문도 인물 ID를 고정한다. 교체 이전 장면을 다시 실행해도 후임의 신뢰나 돈을 바꾸지 않는다.
- 면담 UI는 `meetOpen`에서 상대 인물을 고정하고, 보류 면담 재개와 `meetDo`에서 다시 확인한다. 전환 도우미가 변경된 인물의 열린 면담·보류 면담·인물 상세·동석 보고와 관련 확인창을 닫는다. 다른 구단의 교체는 현재 구단 화면에 영향을 주지 않는다.
- 이전 인물·연락처·초대·예약·동석 보고·주문·면담 원본은 `G.ownershipPeopleHistory`에 저장한다. 기존 동석 관람 이력은 지우지 않고 이름·인물 ID를 보완한다. 중계 재생 위치는 유지하면서 종료된 개인 동석 연결만 제거한다.
- 아바타의 `cimgKey`·`faceKey`는 인물 `pid`를 그대로 사용한다. 확인한 구단주 아바타 경로는 모두 `bossOf(tid).own.id`를 전달한다. 후임이 고유 ID를 받으면 이전 인물의 사진·커스텀 이미지를 물려받지 않으며, 이전 이미지 키는 보존된다. `32_people.js` 수정은 필요하지 않았다.

구단의 승인된 지원금·금전 약정·시설 공사·선수 계약·구단 연대기와 경기 기록은 이 도우미의 정리 대상이 아니다.

## 검증

`node tools/check-ownership-people.cjs` — 16개 통과. 메모리 빌드(`build({write:false})`)로 현재 엔진과 실제 면담 UI 함수를 컴파일한다.

실제 `meetOpen → ownTalkStart → meetKeep → 인물 교체 → 이전 meetDo/ownTalkPick` 경로, 실제 `evPick`와 `gmAttendResult`, 종료된 지시의 일일 판정, 사장만 교체, 타구단 교체, 신규 후임 요청 정상 처리, 저장 후 관계 아카이브 보존, 동일 전환 중복 호출, 커스텀 이미지 분리, UI 전역 없는 엔진 단독 실행을 검사한다. 구단의 금전·공사·계약·연대기 데이터는 전환 전후 동일함도 확인한다. 장기 시뮬레이션이나 디스크 빌드 출력은 실행하지 않았다.


## 코어 연결 독립 검토

실제 `ownershipStart → ownershipDaily → ownershipReplace` 경로를 추가 검사했다. 인수 시 구단주·사장 교체와 개인 상태 종료는 한 번만 처리되고, 승계 시 현 사장과 그 친밀도는 유지된다. 기존 시즌 목표와 평가 성향, 영입 때의 목표 약속, 승인된 지원금, 당해 확정 예산 목표액, 시설 공사와 계약 데이터가 동일함을 확인했다.

매각 추진은 관찰 → 공식 매각 추진 → 인수 협상 → 리그 임시 자금 지원 → 실제 인수 순서로 진행하며, 각 단계의 JSON 저장·복원 뒤에도 다음 단계가 정상 실행된다. 회복 경로는 구단주·사장 교체나 개인 면담 취소 없이 매각 추진만 종료한다. 완료된 전환의 일일 처리를 다시 실행해도 출자가 추가되지 않는다. 조회 100회는 약 12ms였으며 게임 상태를 바꾸지 않았다.

독립 검토에서 완료 설명의 `OWNER.name` 오참조를 발견했으며 총괄 담당자가 `OWNER.label`로 수정한 것을 재확인했다. 추가로 구버전 목표에 `owner` 필드가 없고 이직한 구단의 목표가 `G.clubT[tid].goals`에 보관되어 있으면, 그 구단의 AI 인수 뒤 같은 시즌 복귀 시 평가 성향이 후임 것으로 바뀌는 경계를 실제 `switchTeam` 양방향 경로로 재현해 보고했다. 코어 담당자가 저장된 목표에도 이전 평가 성향을 보완하도록 수정했다. 실제 `switchTeam → 옛 구단 AI 인수 → 저장·복원 → switchTeam 복귀` 회귀검사를 추가하여 목표 수치와 이전 평가 성향이 유지되는 것을 확인했다.
