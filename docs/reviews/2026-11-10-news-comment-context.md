# 뉴스 본문·댓글 맥락 불일치 수정

2026-11-10. 수정 전 기준 `5cc5f8ec`. 기사 선택 화면의 캐시 혼선이 아니라 **댓글 생성에 전달되는 기사 주체와 사건 판정**에서 오류를 재현했다.

## 실제로 나온 잘못된 댓글

같은 fixture에서 수정 전 `newsComments`를 실행한 실제 문구다.

| 기사 내용 | 수정 전 댓글 |
|---|---|
| 「장타력 보강의 과제」, 본문은 우승 후보 타선의 장단점 분석 | “우승 반지 끼는 장면 계속 돌려 봄” |
| 다른 구단의 한국시리즈 우승, 현재 사용자 구단은 블레이즈 | “블레이즈 폼 미쳤다 ㄷㄷ” |
| 발행 당시 선수의 MVP 수상 기사, 이후 그 선수 이름 변경 | “본문에없는현재이름 갓-시즌이었지” |

동일 기사의 팬 게시판 글과 기사 옆 댓글 배열도 달랐다. 단순한 팬의 찬반 의견을 오류로 보지 않았으며, 기사에 없는 우승·구단·사람·완료 결과를 끼워 넣는 모순을 중심으로 검증했다.

## 원인과 변경

- `news()`는 `o.tid`를 타 구단 판정에만 사용하고 기사에 보존하지 않았다. 지금은 구단 ID(0 포함), 당시 구단 별칭·도시, 기사에 실제로 온전히 등장한 선수 이름·참조 ID·종류를 `fanCtx`에 보존한다. 제목/본문 등 원문 지문도 저장한다.
- 기존 `newsBank`는 본문 어디든 “우승”이 있으면 우승으로 분류하고 현재 `G.ps.champ`도 참조했다. 새 `newsContext`는 기사 제목과 본문의 확정 여부를 확인한다. 우승 목표·과거 우승·준우승·우승 감독 경질, 수상 후보·미수상·취소, 협상·결렬, 복귀 예정과 실제 복귀를 구분한다. 질문·초읽기·본문의 미확정 결과는 확정 반응을 만들지 않는다.
- 기존 댓글은 현재 `G.user`, 선수 이름·소속, 팬 여론을 읽었다. 기사 댓글은 발행 시점의 주체와 고정 시드를 사용한다. 이후 단장 이직, 구단 도시/별칭·선수 이름/소속·우승자·여론 변경과 JSON 저장 복원에도 댓글 전체가 유지된다. 닉네임의 구단명도 고정한다.
- 기사 전용 반응은 본문에 없는 계약 연수·투표 차이·타석 활약·퍼레이드 방문 등을 추정하지 않는다. 일반 커뮤니티 공용 문구를 기사에 무작위 삽입하지 않으며, 불명확한 기사에 긍정/부정 사건을 임의로 붙이지 않는다. 다른 팬 게시판 상황의 기존 반응은 유지했다.
- `newsComments`를 엔진에 단일화하고 팬 게시판 기사 글도 같은 함수를 호출한다. 렌더러는 원래부터 같은 기사 객체를 넘기고 있었으며 목록 인덱스 캐시에서 다른 기사를 가져오는 오류는 재현하지 못했다.
- 추가 확인한 감독 wire 글은 현재 `G.mgr`로 과거 제목의 본문과 댓글 분위기를 바꾸고 있었다. 이 좁은 분기도 저장된 `w.t` 원문과 같은 안전한 댓글 생성 경로를 사용한다. 과거 A 감독 선임 뒤 현재 B 감독인 실제 wire 사례를 검사했다. wire 발행 모델 전체는 바꾸지 않았다.

정보 없는 옛 기사는 현재 선수 정보로 당시 사람을 추정하지 않는다. 현재 변경된 구단 이름도 사용하지 않는다. 고정 `TEAM_DEF` 명칭이 원문에 실제 등장할 때만 구단 이름을 복원하고, 과거 사용자 지정 별칭 등 확인할 수 없는 이름은 일반 표현으로 남긴다. 구단 ID만 있다고 기사에 없는 기본 별칭을 넣지 않는다. ID가 없거나 중복돼도 원문 지문을 함께 시드에 사용해 다른 기사의 반응을 재사용하지 않는다.

생산 변경은 다음 세 파일이다.

- `src/engine/media/18_media.js`: 발행 맥락 보존.
- `src/engine/media/81_fan_talk.js`: 순수 맥락 조회·기사 전용 반응·단일 댓글 API.
- `src/ui/media/12_fanboard.js`: 기사 댓글 경로 통일, 감독 wire의 현재 인물 의존 제거.

- 집중 검사 **33/33 통과**. 같은 검사에서 수정 전 **33개 중 28개 실패**를 재현했다. 새 API가 없다는 이유로 실패시키는 방식이 아니라 기존 분류 및 실제 댓글 문구를 검사한다.
- 독립 경계 검사 **8/8 통과**. 질문·초읽기·미수상·본문 미확정, legacy 별칭 변경과 사용자 지정 별칭, 실제 FA 생성자 및 실제 시상식 생성자의 발표 전/후를 포함한다.
- 실제 Chromium **390×844, 768×1024, 1366×900 모두 통과**. 기사 미리보기·댓글 펼침/접기·분류 전환·팬 게시판 대응·저장 복원·후일 상태 변경을 검사했다. 상세 내용은 [UI 독립 검수](2026-11-10-news-comment-context-ui.md)에 남겼다.

기본 검사는 현재 소스를 `build({root,write:false})`로 메모리 컴파일하며 `/tmp` 초안에 의존하지 않는다. `--baseline`은 허가된 읽기 전용 `git show 5cc5f8ec:<path>`로 위 세 파일만 당시 버전으로 메모리 치환한다. 수정 후에도 같은 과거 동작을 재현할 수 있다. 진단 모드이므로 실패 결과를 출력하고 종료 코드 0으로 끝낸다. 기본 검사는 실패 시 오류 종료한다. `/tmp` 후보를 쓰는 `--candidate`는 개발 중 비교 옵션이다.
