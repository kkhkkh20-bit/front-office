# 추가 검수 #116–120: 퓨처스 가용일·등판 부하

최신 main `c372fd88` 기준으로 조사했다. 수정 전 모듈을 동결해 5개 시나리오가 모두 실패함을 확인했다. 월간 리포트 한 줄은 병역 담당이 먼저 수정했으므로, 최초 조회에서 확인한 변경 전 호출을 동결본에 반영해 비교했다. 수정 후에는 관련 경계까지 포함한 13개 검사 모두 통과했다.

공통 가용일 판정은 입단·합류일, 말소·당일 1군 출전, 확인 가능한 부상 이력·실제 복귀일, 대표 차출·출장 정지, 복무·전역, 파견 상태를 확인한다. 주간 로테이션 선정과 기록 생성도 같은 가용 투수 목록을 사용한다. 상무 수비 경험은 실제 호출에서 `futUse`의 기관 옵션으로 넘긴다. 확인할 수 없는 과거 소속·출장 날짜를 새로 추정하거나 기존 성적을 일괄 삭제하지 않는다.

검증 명령: `node tools/check-feedback-futures-96125.cjs`

13개 검사는 실제 `signFree`, `milDaily`, `futuresReport`, `futuresWeek`, `pitchApp`·`loadDaily`, 상무 `futBat`→`posWeek`→전역→구단 복귀 흐름을 포함한다. 같은 날 두 등판·짧은 선발 휴식·역순 입력, 가용 이틀의 타석과 수비 경험, 부상·차출 경계, 구조화 이적 장부만 있는 옛 선수도 확인했다. 해외 파견 중인 투수의 주간 과거 날짜에도 등판이 붙지 않도록 검사했다. 전역 전후 `fuseSeen`·`milPos`를 유지하며 JSON 저장 복원 후 숙련이 다시 적립되지 않는 것도 검증했다. 기존 날짜순 부하·짧은 선발 휴식 관련 검사 2개도 현재 소스를 메모리에서 조합해 통과했다.

증거: `/tmp/feedback-futures-before.log`는 5개 실패, `/tmp/feedback-futures-after.log`는 13개 통과다. 소스를 메모리에서 조합했으며 배포 산출물·커밋·푸시는 변경하지 않았다. 이 작업의 생산 소유 파일은 `48_sim_traits.js`, `46_workload.js`, `07_daily.js`의 퓨처스 호출 범위다. 병역 공통 함수·수비 경험 기관 처리는 해당 담당과 협업했다.
