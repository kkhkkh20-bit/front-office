# 소식함 읽기·방향키·날짜 진행 점수 검수

## 확인한 문제와 변경

- 소식함의 `ibStep`은 화면에 존재하는 `.ibr` 행으로 이동 순서를 제한했다. 모바일에서 본문을 열면 목록 행이 DOM에서 사라져 현재 메일만 남는 문제가 있었다. 목록이 보일 때는 기존 필터를 유지하고, 본문만 표시할 때는 이미 보존된 메일 순서로 이동하도록 수정했다.
- 별도 `53_context_navigation.js`에서 소식함 ↑/↓, 선수·단장·인물 상세 ←/→를 기존 메일·인물 이동 액션에 연결했다. 인물 목록이나 탭 순서를 새로 만들지 않는다. 입력란·편집 영역·슬라이더·선택 목록·대화상자·진행 중·경기 중계·조합 키는 제외한다. 기존 중계의 좌우 한 장면 조작도 유지한다.
- 실제 날짜 진행 경로인 `advProgressPaint`에는 상대·일정만 있고 점수 표시가 없었다. 이미 완료된 경기의 점수를 진행 중 일정판과 상단 날짜에 표시하도록 했다. 기존 `calGame`의 결과 가리기를 그대로 사용하여 예약하거나 끝까지 보지 않은 중계의 점수는 공개하지 않는다.

## 메일 클릭 뒤 페이지 점프 조사

제보된 **1024×5085 Chrome 크기**를 포함하여 1366×900, 768×1024, 390×844에서 확인했다. 100건의 메일, 300줄 본문, 아래쪽 메일 선택, 늦게 로드되는 발신자 사진, 본문을 내린 뒤 같은 메일 재렌더와 다른 메일에서 돌아오는 경우를 검사한다. 문서·창 스크롤과 내부 목록/본문 스크롤을 별도로 측정한다.

현재 Chromium에서는 메일 클릭으로 **페이지 전체가 아래로 점프하는 현상은 재현하지 못했다**. 원인을 확인하지 못한 상태에서 CSS·앵커·전역 스크롤 복원을 임의로 변경하지 않았다. 기존 `ibShowCur`는 선택행을 목록 칸 내부에서만 이동시킨다. 본문을 읽던 위치는 기존 읽기 상태 기능이 보존한다.

## 실행

`CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium REVIEW_OUT=/tmp/inbox-reading-feedback node tools/check-inbox-reading-feedback.cjs`

검사는 현재 소스를 메모리에서 빌드한다(`write:false`). `index.html`이나 배포 출력은 쓰지 않는다. 실제 방향키 이벤트, 슬라이더 기본 동작, 기존 중계 조작, 실제 개막전 계산 중 점수, 미완료 중계 결과 가리기를 확인한다. 최종 소스에서 **1024×5085, 1366×900, 768×1024, 390×844 모두 통과**했다. 결과 이미지는 `/tmp/inbox-reading-feedback/`에 저장했다.

## 사용자 답변 초안

소식함에서 위·아래 방향키로 이전/다음 소식을 읽고, 선수·단장 등 인물 상세에서는 좌·우 방향키로 같은 목록의 인물을 이동할 수 있도록 반영했습니다. 모바일 본문에서 다음 소식 이동이 막히던 부분도 수정했습니다. 경기 진행 중에는 상단 날짜와 일정판에서 끝난 경기의 점수를 함께 볼 수 있으며, 관전 중인 경기 결과는 계속 가려집니다.

메일 클릭 후 화면 전체가 아래로 내려가는 현상은 제보하신 화면 크기와 긴 본문·사진 로드 상황까지 확인했으나 현재 테스트에서는 재현되지 않았습니다. 이 부분은 해결됐다고 단정하지 않고 추가 확인 대상으로 남겨 두었습니다.

추가 시각 검수에서 모바일 상단 결과가 기존 `overflow:hidden`과 날짜 라벨의 블록 배치 때문에 잘리는 문제를 확인했다. 새 진행 중 결과만 날짜 옆 짧은 점수로 배치하고 날짜 라벨을 한 줄로 유지했다. 결과를 그린 뒤 진행판의 상단 위치도 실제 헤더 높이로 다시 계산한다. 최종 검사는 DOM 존재뿐 아니라 점수 글자의 중앙을 실제로 가리키는 요소(`elementFromPoint`)가 그 글자인지 확인해 클리핑·진행판 겹침을 검출한다. 768·390px 결과 이미지를 직접 열어 날짜와 점수가 함께 보이는 것도 확인했다.
