저장 계약은 유지했다. 쓰기/삭제는 기존처럼 판번호를 먼저 예약하고 소유권·본문을 재확인한다. 실패 롤백은 여전히 본문과 예약이 이 작업의 것일 때만 수행한다. 메타가 유실된 슬롯의 복구도 본문과 판번호가 그사이 바뀌면 예전 데이터로 덮지 않는다. 브라우저가 롤백 쓰기까지 거부하는 상황에서 저장소를 강제로 고칠 수는 없다.

상위 작업자의 #124 요청도 같은 `00_core.js`에서 처리했다. `linkMap`은 G 객체 identity와 실제 팀 도시/이름 및 선수 ID/이름/소속/후보 상태를 캐시 키로 확인하여, 같은 날짜의 이름 변경이나 저장 교체에 이전 링크 맵을 재사용하지 않는다. #124의 화면 회귀 검사는 상위 작업자가 별도로 담당한다.

수정 전 비교는 `SAVE96125_BASELINE_DIR` 또는 기본 `/tmp/save-96125-before`의 원본 소스를 사용한다. 제보 9건 모두 수정 전 재현/수정 후 통과했다. 기존 저장 슬롯의 16개 항목과 이전 동시 쓰기·판번호·삭제 경합 회귀도 통과했다. 공통 검증 강화에 맞춰 기존 검사 가짜 게임의 최소 `players/cal/sea.rec` 구조만 보완했고, 이전 드래프트 검사도 `unpack`과 공유 `saveCheck`를 함께 가져오게 수정했다. 기존 `check-save-import.cjs` 역시 최신 소스의 임시 검수 HTML에서 실행하여 가져오기·슬롯 전환·중계 재개·itch 이전 점검을 통과했다.

브라우저 검사에서는 실제 Chromium 탭 두 개와 모바일 별도 문맥에서 다음 8개 시나리오를 실행해 모두 통과했고 pageerror는 0건이었다: quota 가져오기 실패, migration 실패의 실제 상세 화면 유지, 삭제 실패 본문/판번호 유지, 상대 탭 후속 저장, 상대 탭 복구 후 오류 캐시 해제, 실제 경기 기록을 포함한 미확인 주간 요약 복구/다음 저장, 메타 유실 후 재실행 날짜 복구, 시즌 기록이 손상된 로컬 저장 거절/정상 슬롯 복구. 탭의 저장 슬롯은 실제 시작 경로처럼 고정하고, 타 탭 변경 전파를 확인한 뒤 검사했다.
