# 관계도 일괄 면담·안부 연락

## 사용자 안내문

관계도에서 여러 직원을 골라 업무·희망 보직 면담이나 감독과의 업무 조율을 한 번에 할 수 있습니다. 다른 구단 단장도 여러 명을 골라 무료로 안부 연락을 보낼 수 있습니다. 각 대상의 기존 14일 재사용 규칙을 따르며, 처리한 사람과 건너뛴 사람의 사유를 따로 보여 줍니다.

‘전원 선택’은 지금 보고 있는 목록의 대상만 선택합니다. 선택 개수와 실행 가능한 개수를 확인한 뒤 실행할 수 있고, 인물 교체나 이직 뒤에는 이전 선택이 적용되지 않습니다.

## 구현 범위

- 기존 관계도의 **코치·스카우트·데이터팀**, **다른 구단 단장** 두 묶음에 ‘여러 명 선택’을 추가했다. 내 인맥 탭과 다른 묶음의 동작은 유지한다.
- 직원 묶음에 함께 표시되는 감독은 기존 카드에서 계속 볼 수 있지만 직원 일괄 면담 대상으로 선택하지 않는다. 전원 선택도 실제 현재 목록에 표시된 코치·스카우트·분석원만 고른다. 목록에 없는 보조 코치나 전체 리그 직원은 몰래 추가하지 않는다.
- 선택 모드에서는 체크 목록, 선택 인원, 실행 가능 인원, 건너뜀 예상 인원, 전원 선택/해제, 주제 선택과 실행 버튼을 제공한다. 조회·선택은 G를 변경하거나 난수를 소비하지 않는다.
- 면담/안부 가능 여부와 쿨다운은 엔진 조회 API의 현재 결과를 그대로 쓴다. UI가 별도 기한을 계산하지 않는다. 쿨다운 행은 짧은 ‘재사용 대기 + YYYY.M.D부터’ 표시로 읽기 쉽게 만들고, 전체 사유는 접근성 설명과 처리 결과에 보존한다.
- 직원 면담의 두 주제는 **같은 직원에 대한 기존 14일 제한을 공유**한다. 한 주제 뒤 다른 주제로 바꿔 제한을 우회하거나, 실패한 시도 때문에 다음 가능일이 새로 밀리는 처리는 하지 않는다.
- 단장 안부는 기존 `gmContact(tid,'call')`을 사용한다. 새 사비 모임·비용·확률·친분 보너스를 만들지 않는다. 성공·건너뜀 결과와 기존 안부 효과를 사람별로 보여 준다.
- 선택은 현재 직원 ID/단장 ID와 소속 구단을 기준으로 보관한다. 단장이 바뀌면 이전 인물 선택을 제거하며, 이직 시에는 선택 모드를 초기화한다. 실행은 엔진에서 다시 현재 대상과 소속을 확인한다.
- 결과는 완료/건너뜀 각각의 이름·실제 안내문을 보여 준다. 긴 목록과 결과는 패널 안에서 스크롤하며, 모바일 체크 행은 약 50px로 유지한다. 선택 모드를 끝내면 기존 인물 카드 목록으로 돌아간다.

API: `staffTalkBulkView/Bulk(targets,topic,expectedTid)`, `gmContactBulkView/Bulk(targets,expectedTid)`. 직원/GM bulk 엔진과 영구 실행 원장은 별도 엔진 담당 범위다. 이 UI는 실행 후 `save()`를 호출하며, 엔진 원장은 실제 로컬 저장/복원으로 검증했다.

## 실제 브라우저 검증

```sh
node tools/check-bulk-relations-ui.cjs
# root 최종 HTML 검증
BULK_HTML=/workspace/front-office/index.html node tools/check-bulk-relations-ui.cjs
```

1366×768, 390×844, 768×844에서 실제로 다음을 조작한다.

1. 직원 하나에게 기존 개별 면담을 실행해 쿨다운을 만든 뒤 현재 목록을 전원 선택한다. 감독과 목록 밖 보조 코치 fixture는 대상에 포함되지 않는다.
2. 실제 일괄 실행 버튼을 두 번 빠르게 눌러도 한 번만 처리되며, 가능한 직원은 업무관계가 기존 +4만큼 변하고 쿨다운 직원은 변하지 않는다. 완료/건너뜀 인원과 사유를 확인한다.
3. 주제 변경과 같은 주제 재선택 뒤에도 14일 공유 제한이 유지된다. 하루 뒤 조회에서도 다음 가능일은 원래 면담일+14일로 남는다. 개별 선택과 선택 해제를 실제 체크박스로 확인한다.
4. 단장 한 명에게 기존 안부를 보낸 뒤 현재 타 구단 단장 9명을 전원 선택한다. 일괄 안부는 8명 완료/1명 건너뜀이며 구단 현금과 개인 잔액 지출이 모두 0이다.
5. 선택한 단장의 교체, 실제 `switchTeam`, 실제 로컬 저장과 브라우저 새로고침을 실행해 선택 초기화와 엔진 원장 보존을 확인한다.
6. 조회의 G 불변/RNG 0, 목록 내부 스크롤, 카드 가로 넘침, 쿨다운 텍스트의 행 내부 경계, 모바일 행 높이와 브라우저 오류를 검사한다.

직원 수는 게임 생성 결과에 따라 달라지므로 고정 숫자로 가정하지 않고, 실제 현재 목록의 선택 가능 인원과 비교한다. 초기 검증에서는 18~24명 직원 목록 중 쿨다운 1명을 정확히 건너뛰었다.

증거: `/tmp/bulk-relations-ui.log`, `/tmp/bulk-relations-ui/results.json`, 같은 디렉터리의 `*-staff-selected.png`, `*-staff-results.png`, `*-gm-free-results.png`.
