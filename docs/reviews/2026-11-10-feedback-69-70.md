# 피드백 #69–70: 불러오기 드래프트 데이터 보존

기준 main `6652118e`. 수정 전 `10_draft.js`를 `/tmp/draft-data-6395-before.js`에 보관하고 실제 저장 JSON 판독 함수 `unpack()` → `migrateDraft()` 경로에서 재현했다. 배포 출력은 수정하지 않았다.

| 번호 | 판정 | 수정 전 재현 | 수정 및 검증 |
| --- | --- | --- | --- |
| 69 | 재현·수정 | 후보 한 명의 학교만 지운 JSON을 불러오면 `migrateDraft`가 기존 일반 후보 전체를 삭제하고 새 후보를 생성. 관심 순서에 옛 ID가 남고 메모/관찰과 인물 연결이 끊김 | 기존 후보/ID/풀 순서/능력/아마 기록/단장 관찰/관심 순서/메모를 보존. 학교·권역 표시만 보완하며 근거 없는 학교와 아마 성적을 생성하지 않음. 학교가 없으면 '학교 정보 없음'. 풀이 작아도 다시 뽑지 않음 |

불러오기에서 후보 명단 필드만 사라졌으면 살아 있는 후보 ID로 복원한다. 실제 존재하지 않는 후보 참조와 중복 참조만 제거하며, 후보 인물은 삭제하지 않는다. 진행 중인 드래프트 명단도 같은 ID를 유지한다. 살아 있는 후보가 전혀 없고 진행 중/금년도 완료 드래프트도 없을 때만 기존 새 후보 생성 경로를 사용한다.

보관 기록은 마지막 소속 구단·이름으로 지명 구단을 추정하지 않는다. 연도와 구단만 명시된 옛 archive는 선수와 WAR를 성적표에 포함하되 순번을 `?-?`로 표시한다. 순번을 모르는 선수는 스틸픽/상위 지명 실패 기사 판정에 쓰지 않는다. 복원한 `dlog`의 연도 키 덕분에 보관 선수만 남은 연도도 기존 `draftYears`와 성적표 탭에서 발견된다. 다른 UI 파일을 고치지 않았다.

검사:

```sh
git show 6652118e:src/engine/draft/10_draft.js > /tmp/draft-data-6395-before.js
node tools/check-feedback-draft-data-6395.cjs --baseline
node tools/check-feedback-draft-data-6395.cjs
```

두 명령 모두 통과했다. baseline 모드는 수정 전 10번 엔진 소스를 메모리 엔진에 넣어 두 건의 데이터 손실을 확인한다. 기본 모드는 JSON `unpack`/마이그레이션 후 실제 `draftPool`, `myBoard`, `draftYears`, `draftHist` 출력에서 후보 링크·메모·은퇴자·WAR 합계를 검사한다. 추가 검사는 작은 풀, 깨진 ID, 명단 필드 유실, 진행 중 명단, 반복 불러오기, 보관 연도 발견, 미상 순번, 지명 구단 근거 없음, 현역+보관 합계, ID 중복, 기존 dlog 중복 방지를 포함한다. 화면 함수는 소스에서 추출한 실제 함수이며 배지·레이아웃 같은 표시 유틸리티만 검사 대역이다.

변경 파일은 `src/engine/draft/10_draft.js`, 집중 검사, 본 보고서다. 별도 #77 담당자 요청으로 `11_founding_draft.js`의 기존 지명 당시 평가 `p.dEst` 저장 한 곳에 원 구단·연도·날짜(`tid/y/d`) 3개 필드만 추가했다. 다른 11번 로직 및 다른 담당자의 63/88/UI31 소스는 변경하지 않았다.

한계: 과거에 이미 삭제된 후보의 이름·능력·관찰·메모를 근거 없이 복원하지 않는다. 지명 연도/구단 정보가 없는 archive도 새로 귀속시키지 않는다. 검사는 메모리 `build({write:false})`만 사용했고 정식 빌드·커밋·푸시는 상위 작업자가 담당한다.
