# 구단 공개 프로필·연대기 UI — 2026-11-10

타구단의 자료를 조회하기 위해 `G.user`를 바꾸던 우회 없이, `UI.clubInspect`와 구단별 탭 상태로 공개 프로필을 연다. 기존 구단 요약 창의 **구단 정보·연대기** 버튼이 진입점이다. 현재 선수단 보기와 트레이드 진입은 유지한다. 운영 권한은 현재 담당 구단에 그대로 남는다.

## 구현

- **개요:** 실제 보유 현금, 샐러리캡 산정액, 구단 명성·운영 방침·구단주, 관중, 보관된 구장·훈련 시설과 투자 이력. G.history[].fins의 실제 결산을 모아 연도별 수입·지출·손익·기말 현금 표와 연도별 세부 장부를 표시한다. 옛 저장의 G.last.fins도 같은 연도에 중복되지 않게 보충하고, 없는 연도는 추정하지 않는다. 타구단 팬 여론은 실제 이직 저장 위치 `G.clubT[tid].pr`의 값을 마지막 보관값으로 표시하며, 없으면 기록 없음으로 표시한다. `G.orgT`는 영구결번·의료 등의 장부이므로 팬 여론 조회에 사용하지 않는다. 우리 구단 예산·팬 여론·시설을 가져다 채우지 않는다.
- **선수단:** 해당 구단의 현재 선수와 포지션·나이·연봉·계약·등록 상태. 선수 상세를 닫으면 공개 프로필로 돌아온다.
- **운영진·스태프:** 구단주·사장·단장·감독·1/2군 코치·보조 코치·스카우트·분석원을 실제 구단별 장부에서 읽는다. 접어서 보는 상세에 재임·계약·경력·능력·성향을 표시한다. 다른 구단의 해고·채용·시설 투자·면담 버튼은 제공하지 않는다.
- **시즌·명예:** 구단별 트로피·영구결번, 모든 보관 시즌의 성적과 실제 포스트시즌 결과, 역대 단장, 수상·인사 기록을 표시한다. 순위 5위 이내라는 이유만으로 포스트시즌 출전을 추정하지 않는다.
- **구단 통산 기록:** 현역과 은퇴 보관선수의 해당 구단 1군 구간만 합친다. 현재 소속으로 필터하지 않으며 `y2` 합계 줄과 다른 구단 구간은 제외한다. 타자는 WAR·안타·홈런·타점·도루, 투수는 WAR·승·세이브·탈삼진·이닝으로 정렬하고 20명씩 모든 선수를 넘겨 본다.
- **연대기:** 우리 구단과 공개 구단이 공통 `clubChron(tid)` 조회를 사용한다. 전체 보존 기록에 연도·종류 필터, 최신순 40건 페이지와 내부 스크롤을 제공한다. 날짜가 남지 않은 옛 기록에는 연도와 일자 기록 없음, 보충 기록에는 실제 근거 장부를 표시한다. 이벤트 문구는 당시 이름·계약 내용이 담긴 고정 문자열을 표시한다.
- 기존 FM 구단 정보의 최근 구단 기록 12건도 `clubRecords(tid)`로 영구 장부에서 읽는다.
- PC 뒤로·앞으로는 조회 구단과 탭을 기억한다. 구단별 탭 상태를 따로 보관하고, 우리 메뉴로 이동하면 공개 조회를 종료한다. 공개 조회 중에는 상단의 우리 구단 예산 칩을 노출하지 않는다.

## 읽기 전용 보호

`teamProfile(tid)`의 다섯 탭을 직접 조회하기 전후 `JSON.stringify(G)`가 같은지 검사한다. 기존 도우미의 쓰기 부작용도 피했다. `warOf`의 과거 WAR 캐시는 선수 `pw` 복사본에서 계산하고, 선수 사진은 이미 배정된 사진만 읽는다. 새 사진 배정이 필요한 선수는 이니셜을 보여 준다. `stadOf`, `facSt`, `gmOf`, `stTeamL`, `bossOf`로 조회 중 없는 상태를 생성하지 않는다.

기존 OB 스카우트 즉시 영입 동작에는 실제 성공 직후 `staffHistory('scout', s, '선임', G.user, ...)` 기록을 추가했다.

## 검증

`tests/tools/check-club-profile-ui.cjs`를 실행했다. 배포 `index.html`·`dist/engine.js`는 쓰지 않고 `build({write:false})` 결과를 `/tmp/club-profile-working.html`에만 생성한다.

1366×768, 390×844, 768×844 세 화면에서 다음을 실제 Playwright 클릭과 상태 비교로 확인했다.

- 구단 요약 → 공개 프로필 → 다섯 탭 → 선수 상세 → Esc → 원래 공개 프로필.
- 모든 프로필 조회의 게임 상태 불변, 실제 담당 `G.user` 불변, 타구단 운영 버튼 없음.
- 실제 `G.pr.fan=17 → switchTeam(1) → 옛 구단 공개 프로필` 경로에서 보관 여론 17 표시, 새 담당 구단 유지, 조회 전후 게임 상태 불변.
- 같은 해 다른 구단에서 낸 9,999안타와 `y2` 9,000안타를 제외하고 해당 구단의 13안타·7홈런만 합산. 은퇴 보관 선수의 해당 구단 17안타도 포함.
- 홈런 정렬 내림차순, 다음 선수 페이지의 21번째 순위 표시.
- 실제 2025/2024 장부의 수입·손익·현금, 연도 내림차순, 옛 G.last 장부 보충, 같은 연도 중복 방지, 연도별 세부 수입·지출 접기.
- 40건 연대기 페이지 이동, 코치 기록 종류 필터, 페이지 초기화, 내부 스크롤, 다른 구단 기록 미혼입.
- PC 뒤로·앞으로, 구단별 탭 기억, 우리 메뉴 진입 시 조회 해제, 리그 복귀.
- 각 탭에서 문서 가로·세로 넘침 없음, 브라우저 `pageerror` 0건.

결과와 화면: `/tmp/club-profile-ui/results.json`, `/tmp/club-profile-ui/<폭>-overview.png`, `-roster.png`, `-staff.png`, `-honors.png`, `-chron.png`, `-former-club-fan.png`. 1366 연대기와 390 개요·연대기 스크린샷을 열어 배치도 확인했다.

이 UI는 없는 옛 자료를 복원하거나 추정하지 않는다. 보관 기록의 영속성·AI 이벤트 생성은 공통 엔진 작업과 연결되며, 자료가 없는 과거 재정·팬 여론·개인 기록은 기록 없음으로 남는다. 기존 진행 멈춤·로스터 복구 설정과 생성된 배포 파일은 수정하지 않았다.

통합 검증에서는 `CLUB_PROFILE_HTML=/workspace/front-office/index.html`로 실제 배포 빌드도 같은 세 폭에서 검사했다. 실제 이직 후 옛 구단 팬 여론 17 표시와 조회 상태 불변을 포함해 통과했다.

## 태블릿 홈 순위표 회귀 점검·수정

최종 `check-home-fit`가 1024×768에서 순위표 마지막 행의 초기 잘림을 발견했다. `git show HEAD:index.html`의 HEAD `69f146b9`와 이번 빌드 모두 동일하게 재현돼, 이번 공개 프로필 작업에서 생긴 회귀는 아니었다. 기존 카드 높이는 266px인데 머리줄 41px 외에 표가 높이 100%와 24px 행을 요구해, 마지막 두 구단은 카드 안을 42px 내려야 볼 수 있었다.

사용자의 홈 한 화면 요구에 맞춰 승인 후 `src/css/home/25_home_workspace.css`에서 **700~1099px의 `data-device="tablet"` 홈 순위표만** 수정했다. 표는 머리줄을 제외한 남은 높이를 쓰고, 셀은 20px·구단 링크는 18px로 배치한다. 글꼴 크기는 줄이지 않았다. 실제 1024×768 측정에서 셀·링크 글꼴은 기존 13px, 표 높이 223px, 마지막 행 끝 661.5px로 카드 끝 663px 안에 들어왔다. 카드 `scrollHeight`와 `clientHeight`는 모두 264px이며 10개 구단을 스크롤 없이 읽을 수 있다.

`build({write:false})`로 `/tmp/club-home-tablet-working.html`만 생성하고 다음 검사를 통과했다.

```sh
REVIEW_HTML=/tmp/club-home-tablet-working.html node tools/check-home-fit.cjs
```

통과 화면은 1280×600, 1366×768, 1366×900, 1920×1080, 1024×768, 768×1024, 390×844, 390×667이다. 배포 산출물은 이 점검에서 쓰지 않았다. 비교 증거는 `/tmp/club-home-probe/{head,current,tablet-fix}.json`과 같은 이름의 `-1024-before.png`, `-1024-after.png`다.
