# 관계도 일괄 면담·단체 안부

일괄 처리는 기존 한 명씩 실행하던 면담과 연락을 선택한 대상에게 순서대로 적용한다. 개인별 조건이나 관계 효과를 새로 완화하지 않는다. 엔진 담당 파일은 `52_staff_profiles.js`, `83_personal_life.js`이며 UI는 관계도 담당자와 API를 합의했다.

## 직원 면담

`staffTalkCheck`를 단일 `staffTalk`와 일괄 처리의 공통 검사로 쓴다. 현재 재직 중인 코치·보조 코치·스카우트·전력분석원만 처리한다. 업무·희망 보직 면담은 기존 단장 관계 +4, 감독과의 조율은 단장 관계 +2 및 감독 관계 +3이다. 두 행동은 기존처럼 같은 직원의 14일 면담 대기 시간을 공유한다. 감독이 없으면 조율만 건너뛰며 일반 업무 면담은 가능하다. 계약 기간은 변경하지 않는다.

한 번의 실행에는 사용자가 고른 한 행동만 적용한다. 업무 면담과 감독 조율을 서로 다른 사람에게 나누려면 대상을 나눠 각 행동을 명시적으로 실행한다. 어떤 직원이 대기 중이거나 퇴직했더라도 다른 유효한 직원은 계속 처리한다. 중복 선택한 같은 ID에는 한 번만 적용한다.

## 타 구단 단장 안부

기존 `gmContact(tid, 'call')`를 그대로 호출한다. 원래 안부 연락은 무료이며, 각 구단 단장별 14일 간격과 성향별 구단 관계 증가가 있다. 일괄 연락도 동일하다. 개인 지갑·구단 현금은 차감하지 않고, 유료 사비 식사의 개인 친밀도 보상도 추가하지 않는다. `personalActivity('network')`의 유료 식사나 정보만 얻는 `gmPersonalReply`는 변경하지 않는다.

선택 당시의 구단과 인물 ID를 함께 받는다. 그 자리에 다른 단장이 취임했다면 선택한 전임자 대신 후임에게 연락하지 않는다. 이미 연락한 구단은 그 행만 건너뛰고 나머지 연락을 계속한다.

## API와 실행 기록

- `staffTalkBulkView(targets, topic, expectedTid)` / `staffTalkBulk(...)`
- `gmContactBulkView(targets, expectedTid)` / `gmContactBulk(...)`

직원 대상은 `{kind, id, tid?}`, 단장 대상은 `{tid, id}`다. 직원의 `topic`은 `listen` 또는 `coord`이며 실행 전체에 명시한다. 선택 때 저장한 `expectedTid`를 실행에도 전달한다. 단장이 이직했거나 사용자가 무직이면 기존 선택으로 실행하지 않는다.

조회는 게임 상태나 난수 흐름을 바꾸지 않는다. 누락된 분석원이나 AI 단장을 조회 때문에 새로 생성하지 않는다. 실행 직전에도 각 대상의 현재 조건을 다시 확인한다.

결과에는 대상별 `ok`, `reason`, `msg`, 필요하면 `nextDay`와 `cost`, 성공·건너뜀 배열 및 합계가 있다. `G.bulkTalkHistory`에는 실행 ID·날짜·그때의 구단·선택 당시 구단·행동·대상별 실제 결과·합계·비용을 별도 스냅숏으로 보존한다. 모든 대상이 건너뛰어진 실행도 사유를 남긴다.

## 검증

`node tools/check-bulk-talk.cjs` — **12개 통과**. 현재 소스를 `build({write:false})`로 메모리 컴파일한다. 기존 단일 면담과 일괄 면담의 관계·쿨다운 동등성, 같은 난수 시드에서의 기존 개별 단장 통화와 일괄 결과 동등성, 지갑 무변경, 중복 선택, 퇴직·감독 부재, 두 행동의 공유 대기 시간, 단장 교체, 실제 구단 이직 후 오래된 선택, 무직 상태, 결과 원장의 저장 복원, 순수 조회와 RNG 무소비를 확인한다.
