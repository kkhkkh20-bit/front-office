# 경기 화면 에셋 검토 (2026-11-03)

사용자 선호: 경기 중 왼쪽 앱 탐색 메뉴는 숨기고 실제 상단바는 유지한다. 타자 뒤에서 투수를 보는 시점이 우선이지만, 컴프매·백년야구처럼 위에서 내려다보는 방식도 허용했다. 기존 게임의 그림을 가져오는 요청은 아니다.

## 권장 구현

기존 에셋을 활용하는 위에서 본 2D 중계를 적용했다. 구장과 선수 움직임을 중심에 두고, 현재 타자·투수 카드와 우측 하단 3×3 투구판·B/S/O를 결합한다. 투구판에는 존 밖의 볼도 표시할 여백을 둔다. 수비·주루는 기존 경기 기록의 이동 결과에 연결한다.

앞서 생성한 사실적인 타자 뒤 시점 이미지는 구도 제안이다. 해당 이미지는 재사용 가능한 선수 모델·애니메이션·구장 세트가 아니다. 같은 수준의 3D를 구현하려면 야구 유니폼 선수 모델, 좌우 투타 동작, 포수·심판 자세, 수비·송구·주루 동작, 구장 모델과 브라우저 렌더링 작업이 별도로 필요하다. 현재 그런 일체형 패키지를 확보했다고 보고하면 안 된다.

새 경기는 `src/core/pitches.mjs`에서 기존 타석 확률 모형의 결과에 조건부로 공별 사건을 구성한다. 실제 경기 추적 자료가 아니라 시뮬레이션 좌표다. 당시 활성 구종과 구속, 합법적인 카운트, 위치, 결과를 `pbp[15]={v:1,pitches:[...]}`에 보존한다. 볼넷 최소 4구·삼진 최소 3구를 보장하고 투수 투구 수도 기록 개수와 맞춘다. 별도 난수원을 써 기록 생성 자체는 경기 난수를 소비하지 않는다. 다시 볼 수 없는 게임 시작 전 과거 시즌은 기존 모형을 유지해 초기 세계·후보 생성과 준비 성능을 보존한다. 최소 투구 수 보정은 이후 피로·교체 시점에 영향을 줄 수 있다.

투구판은 새 경기의 저장된 공만 재생하며 현재 선수 능력이나 미래 타석을 읽어 과거 투구를 바꾸지 않는다. 공별 자료가 없는 옛 저장은 기존 타석 결과를 바탕으로 재구성하고 화면에 **투구 재현**으로 표시한다. 실제 관측 자료나 선수 분석용 코스별 강약점으로 쓰지 않는다.

## 이번에 반영한 범위

경기 중 `.cast-page-open`으로 앱의 왼쪽 탐색 메뉴만 숨긴다. 실제 상단바와 휴대폰 하단 탐색은 유지한다. 헤더·사이드 영역을 측정하는 기존 `appFrameSync`를 통해 경기 본문이 왼쪽 끝까지 넓어진다. 선수 상세·일반 화면으로 이동하면 메뉴가 복원된다. 이후 2026-11-03i에서 큰 구장·타자/투수 카드·9칸 투구판·공별 기록을 연결했다. 기록·선수단은 별도 보기로 전환한다. 3D 카메라·모델 도입은 하지 않았다.
