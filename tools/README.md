# 점검·정리 도구

처음 한 번: `npm install && npx playwright install chromium`

- `check.sh`: 빌드 → 문법 → 정적 점검 → 장기 시뮬(시드 2개) → 화면 점검을 한 번에 돌립니다. `QUICK=1`이면 빠르게.
- `check-static.js`: 소스만 읽어 이름 충돌(나중 선언이 앞을 덮어씀)과 초기화 전 사용(맨 위 코드나 그 코드가 부르는 함수가 뒤 파일의 상수를 씀)을 찾습니다. 일부러 덮어쓰는 이름은 `dup-allow.txt`에 적습니다.
- `check-logic.js`: '오류는 안 나지만 결과가 틀린' 버그를 시나리오로 확인합니다(상황 만들기 → 기능 실행 → 기대 결과 비교). 리뷰·플레이에서 나온 버그는 고치기 전에 여기에 먼저 넣고, 수정 전 버전에서 실패하는 것을 확인한 뒤 고칩니다.
- `check-sim.js [끝 연도]`: 엔진만으로 여러 시즌을 돌립니다. 예외, 빈 `catch`가 삼킨 숨은 오류(점검할 때만 드러냄, 소스는 그대로), NaN·음수 연봉·이상한 나이, 진행 멈춤(이유 표시)을 보고합니다. `SEED`, `TEAM`, `STRICT=1`(숨은 오류도 실패로).
- `check-ui.js [index.html]`: 브라우저로 실제 화면을 열어 봅니다. 첫 화면, 새 게임, 모든 메뉴·하위 메뉴·안쪽 탭, 선수 정보 모든 탭, 사람·기자 카드, 협상 창, 스페이스바 진행을 시즌 준비·시즌 중·FA·야인 시점에서 확인하고, 화면마다 버튼을 무작위로 눌러 봅니다(`MONKEY`=화면당 횟수, `MSEED`=시드). 예외·콘솔 오류·숨은 오류·빈 화면을 모아 보고합니다. `W=390`이면 휴대폰 화면, `QUICK=1`이면 시즌 준비만, `HIDDEN=0`이면 숨은 오류 드러내기를 끕니다.

## 정리 도구

- `find-dead-code.js`: 어디서도 부르지 않는 최상위 함수·상수를 찾습니다. `--apply`를 붙이면 지웁니다. 같은 이름이 두 번 선언된 경우도 알려 줍니다(나중 선언이 앞을 덮어쓰므로 버그 원인이 됩니다). 실행하려면 `npm i acorn acorn-walk`가 필요합니다.
- `find-dead-css.py`: 소스 어디에도 나오지 않는 클래스만 쓰는 CSS 규칙을 찾습니다. `--apply`를 붙이면 지웁니다. 클래스 이름을 문자열로 이어 붙여 만드는 경우(`net${lv}`, `t-${tab}`, `'v-'+k`)는 예외로 둡니다.

둘 다 지운 뒤에는 빌드, 회귀 검사, 같은 시드 화면 비교로 결과가 같은지 확인합니다.
