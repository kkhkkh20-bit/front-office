# 점검·정리 도구

처음 한 번: `npm ci && npx playwright install chromium`

- `build.cjs`: `src/modules.json` 검증 후 공용 모듈과 게임·화면을 단일 HTML로 묶습니다. `--check`는 파일을 쓰지 않고 검사, `--engine-out /tmp/e.js`는 엔진만 별도 출력합니다.
- `test/modules.test.cjs`: 공용 모듈 계산과 참조 경계, 소스 목록, 부팅 순서, 빌드 재현성과 실패 시 출력 보존을 검사합니다.
- `check.sh`: 빌드 → 문법 → 정적 점검 → 장기 시뮬(시드 2개) → 화면 점검을 한 번에 돌립니다. `QUICK=1`이면 빠르게.
- `check-static.js`: 소스만 읽어 이름 충돌(나중 선언이 앞을 덮어씀)과 초기화 전 사용(맨 위 코드나 그 코드가 부르는 함수가 뒤 파일의 상수를 씀)을 찾습니다. 일부러 덮어쓰는 이름은 `dup-allow.txt`에 적습니다.
- `check-logic.js`: '오류는 안 나지만 결과가 틀린' 버그를 시나리오로 확인합니다(상황 만들기 → 기능 실행 → 기대 결과 비교). `ONLY=문구`로 이름에 그 문구가 든 시나리오만 돌릴 수 있습니다. 리뷰·플레이에서 나온 버그는 고치기 전에 여기에 먼저 넣고, 수정 전 버전에서 실패하는 것을 확인한 뒤 고칩니다.
- `check-sim.js [끝 연도]`: 엔진만으로 여러 시즌을 돌립니다. 예외, 빈 `catch`가 삼킨 숨은 오류(점검할 때만 드러냄, 소스는 그대로), NaN·음수 연봉·이상한 나이, 진행 멈춤(이유 표시)을 보고합니다. `SEED`, `TEAM`, `STRICT=1`(숨은 오류도 실패로).
- `check-ui.js [index.html]`: 브라우저로 실제 화면을 열어 봅니다. 첫 화면, 새 게임, 모든 메뉴·하위 메뉴·안쪽 탭, 선수 정보 모든 탭, 사람·기자 카드, 협상 창, 스페이스바 진행을 시즌 준비·시즌 중·FA·야인 시점에서 확인하고, 화면마다 버튼을 무작위로 눌러 봅니다(`MONKEY`=화면당 횟수, `MSEED`=시드). 예외·콘솔 오류·숨은 오류·빈 화면을 모아 보고합니다. `W=390`이면 휴대폰 화면, `QUICK=1`이면 시즌 준비만, `HIDDEN=0`이면 숨은 오류 드러내기를 끕니다.

## 맞춤 도구

- `check-workspace-space.cjs`: 모바일 3종·태블릿 가로/세로·PC·낮은 가로 화면에서 모든 업무 메뉴와 내부 탭·보고 묶음을 열고, 선택창 높이·목록 공간·필터 펼침을 확인합니다. 실제 터치 스크롤과 소개/이미지 뒤 표 머리글 고정도 확인합니다. `REVIEW_OUT`은 화면·측정 결과 저장, `REVIEW_WIDTHS=390,568`은 화면 폭 선택, `GESTURES_ONLY=1`은 터치와 표 고정만 빠르게 확인합니다.
- `check-career-rules.cjs`, `check-career-review.cjs`: 단장이 교체될 때 개인 친분과 구단 관계 구분, 실제 대화 상황, 활동 상대 선택 유지와 빠른 설정 변경을 검사합니다.
- `check-reading-navigation.cjs`: 관전 보고 닫기·다른 결과 보고의 위치·긴 면담의 새 답변 표시와 읽기 위치를 검사합니다.
- `check-season-playthrough.cjs`: 휴대폰·태블릿·PC에서 다른 구단으로 실제 계속·소식 결정·경기 결과·선수 카드·면담을 조작하며 한 시즌과 저장 후 재접속을 확인합니다. `PLAY_CASES=phone,tablet,pc`, `PLAY_TURNS=180`, `PLAY_OUT=/tmp/front-office-season-review`로 범위를 정합니다. 전체 점검에서는 `LONG_PLAY=1`일 때 실행합니다.

- `check-pitches.cjs`: 저장된 공과 9칸 투구판·구종·구속·좌표·B/S/O를 대조합니다. PC/휴대폰 배치, 재생·일시정지·팀 전환, 저장 후 재생과 예전 기록의 재현 표시도 확인합니다. `CAPTURE=1`이면 `/workspace/front-office-pitches-폭.png`로 화면을 남깁니다.
- `check-viewport.cjs`: 모든 메뉴·하위 탭·선수 상세·중계를 휴대폰 세로(360·390)·가로(844×390)·태블릿·노트북(1280×600 포함)·PC·대형(2560) 화면에서 열고 가로 넘침, 화면 밖 요소, 넘침 숨김에 일부가 잘린 버튼, 다른 요소에 가려진 버튼, 200px보다 납작한 경기장을 찾습니다. `SIZES=390x844,844x390`, `VIEWS=home,cast`로 골라 돌릴 수 있습니다.

- `fit-frec.js`: 외국인 후보의 기록 해석표(`12_foreign.js`의 `FREC`)를 다시 맞춥니다. 후보 생성 방식(리그 비중, 능력 분포, `LG_ADJ`, `FENV`, MLB 경력)을 바꾸면 돌리고, 출력된 한 줄로 표를 바꿉니다. 추천순과 종합 추정이 이 표를 씁니다.

## 정리 도구

- `find-dead-code.js`: 어디서도 부르지 않는 최상위 함수·상수를 찾습니다. `--apply`를 붙이면 지웁니다. 같은 이름이 두 번 선언된 경우도 알려 줍니다(나중 선언이 앞을 덮어쓰므로 버그 원인이 됩니다). 실행하려면 `npm i acorn acorn-walk`가 필요합니다.
- `find-dead-css.py`: 소스 어디에도 나오지 않는 클래스만 쓰는 CSS 규칙을 찾습니다. `--apply`를 붙이면 지웁니다. 클래스 이름을 문자열로 이어 붙여 만드는 경우(`net${lv}`, `t-${tab}`, `'v-'+k`)는 예외로 둡니다.

둘 다 지운 뒤에는 빌드, 회귀 검사, 같은 시드 화면 비교로 결과가 같은지 확인합니다.

소스 위치와 순서는 `src/modules.json`을 따릅니다. 정리 도구와 에셋 생성 도구도 같은 목록을 읽습니다. `find-dead-code.js`는 호환 게임·화면 스크립트 대상으로 사용하고, 공용 ESM의 연결 여부는 모듈 검사에서 확인합니다.

화면 검사는 `lib/ui-server.cjs`로 검사 프로세스 안에서 HTML 하나만 제공합니다. 별도 HTTP 서버나 실행 보조 코드가 필요하지 않습니다. 시스템 브라우저는 `CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium`으로 선택하고, 미지정 시 Playwright 기본 브라우저를 사용합니다.
