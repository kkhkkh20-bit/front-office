# v20 감독·코치 고화질 — 1명 통과, 59명 보류

**600장 전체 납품은 완료되지 않았습니다.** `assets/v20-review`의 부분 검토본입니다. `validation.json`의 `passed`와 `request_fulfilled`는 의도적으로 `false`이고, `published_subset_passed`만 `true`입니다. main 병합 및 게임 코드 수정은 하지 않았습니다.

사용자는 2026-11-16에 **“모든 수치 기준 우선, 얼굴 변경이 필요하면 해당 인물 보류”**를 선택했습니다. 따라서 원본 얼굴을 다른 얼굴로 바꾸거나, ArcFace 점수를 보정하거나, 0.40 기준에 예외를 두지 않았습니다.

기존 v7 감독·코치 60명의 얼굴·나이·안경·수염 정보를 확인하고, 전원에게 두 가지 촬영 구도의 고화질 후보를 제작했습니다. 가까운 후보 및 구단 버전까지 총 178장 후보를 생성했습니다. 원본 v7 참조 사진 자체도 256px에서 60명 모두 다른 기존 인물과 0.40 이상인 쌍이 있었습니다. 이는 기존 중복의 실측 기록이며, 새 사진 검수의 예외 사유로 사용하지 않았습니다.

최종적으로 **`v7_staff01_coach_035` 한 명의 10구단 사진만 모든 기준을 통과**했습니다. 다른 59명은 현재 후보에서 통과하지 못해 보류했습니다. 보류가 수학적으로 불가피하다고 주장하는 것은 아닙니다. 현재 제작한 후보와 엄격한 검수 결과를 그대로 넘깁니다. 인물별 실패 점수는 `validation/held_identities.json`에 있습니다.

## 연결 범위

전체 코치 사진을 일괄 교체하지 마세요. `manifest.identities[].status === "ready"`인 인물만 연결할 수 있습니다. 현재 대상은 35번, 원본 manifest의 **0-based slot34**입니다. 59명은 `status: "held"`, `variants: {}`이며 기존 사진을 유지해야 합니다.

큰 감독·코치 카드에는 384, 목록에는 128을 사용합니다. 256도 제공합니다. 인물별 `variants[team].sheets[size].path`와 `rect`를 그대로 사용하세요. 60명 순서와 나이·tags는 v7과 일치합니다. 30개 시트는 요청한 10×10 크기를 유지하며, 보류 인물의 사진 rect와 미사용 40칸은 검은 빈칸입니다. 보류 인물 자리에 통과자의 얼굴을 복제하지 않았습니다.

| 크기 | pitch | rect | 인코딩 |
|---|---:|---|---|
| 384 | 400 | `[col*400+8,row*400+8,384,384]` | RGB WebP q89 |
| 256 | 272 | `[col*272+8,row*272+8,256,256]` | RGB WebP q88 |
| 128 | 144 | `[col*144+8,row*144+8,128,128]` | RGB WebP q85 |

30장 합계는 **755,864바이트**입니다. 인물 한 명만 차 있으므로 전체 60명분 용량으로 해석하지 마세요.

## 검수 결과

실제 최종 WebP를 디코딩하고 rect를 잘라 얻은 30개 사진을 검사했습니다. 같은 픽셀을 독립 재측정하는 `validation/recheck.py`도 통과했습니다.

| 크기 | 기존 동일인 최소 ≥0.60 | 다른 기존 인물 최대 <0.40 | 10구단 45쌍 동일인 최소 ≥0.60 |
|---|---:|---:|---:|
| 128 | 0.66094875 | 0.39215970 | 0.81147456 |
| 256 | 0.76005358 | 0.39893550 | 0.87479538 |
| 384 | 0.76443315 | 0.39916360 | 0.88544226 |

비교 대상은 v7 126명, v6c 100명, v13 60명, v18 200명, 총486명의 기존 canonical 얼굴입니다. 사진마다 자기 v7 ID 하나만 제외한 485명 전부와 비교했습니다. v13 canonical ID는 기존 갤러리의 `v6d60_001..060`입니다. 128은 기존128 참조, 256·384는 기존256 참조를 사용했습니다. 원래 갤러리와 동일한 SCRFD/ArcFace 모델·정렬·L2 정규화·raw cosine이며 whitening, 점수 변환, 기준 완화는 없습니다.

최종 다른 인물 비교는 14,550회, 구단 간 동일인 비교는 135회(크기별45쌍)입니다. 60명 전체의 크기별2,700쌍을 검사한 것으로 표시하지 않았습니다. 정확한 모델 해시와 프로토콜은 `validation/protocol.json`, 실제 픽셀 해시·랜드마크는 `validation/final_pixel_measurements.json`, 원시 점수 행렬은 `validation/raw_reference_scores.npz`에 있습니다.

## 사진과 원본

통과 사진은 생성 원본의 623×623 전체 사진 crop 9장과 1254×1254 전체 사진 1장에서 바로 줄였습니다. 128px 확대, 얼굴·몸통·모자 붙이기, 얼굴 비율 변형은 하지 않았습니다. 2×2 원본의 경계만 전체 사진을 같은 비율로 2px씩 잘라 정리했습니다. 모자는 깊게 눌러 썼고, 나이 든 피부의 주름과 질감을 유지했습니다. 홈킷 기준의 가슴 표시만 사용했습니다.

`sources/native/`의 30개 무손실 RGB WebP는 실제 생성 원본의 RGB 픽셀과 완전히 같음을 검증했습니다. `index.json`에 원본 파일 SHA256, RGB SHA256, 보관판 SHA256이 있습니다. 원래 PNG는 작업 환경의 생성 원본 폴더에도 그대로 남겨두었습니다. v7 원본 ZIP 출처와 Git 커밋은 `validation/source_commits.json`에 있습니다. v7의 알파에는 모자 겹침용 데이터가 있으므로 얼굴 참조는 알파를 합성하지 않고 RGB를 사용했습니다.

```bash
python assets/v20/staff60/validation/recheck.py
cd assets/v20/staff60
sha256sum --check checksums.sha256
```
