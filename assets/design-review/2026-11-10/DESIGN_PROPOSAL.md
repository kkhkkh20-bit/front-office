# 플레이 리뷰와 디자인 제안

## 먼저 고칠 순서

사진을 늘리는 것보다 **핵심 화면으로 들어가는 길을 보이게 하는 것**이 먼저입니다. 그 다음, 서로 다른 연수와 의료 단계의 의미를 작은 장면과 핵심 수치로 구분하는 것을 권합니다. 홈·선수단·시장은 현재 정보 밀도를 유지합니다.

P0 원인 후보는 `src/ui/components/51_table_pager.js` 104~105행입니다. `.seg`를 포함한 제어 요소를 모두 `details.ws-filter-controls`로 옮기는 공통 처리에서 `.seg.itabs`까지 묶입니다. 실제 모바일에서 닫힌 details 안에 `[data-a="itab"][data-v="devv:ovs"]`가 들어 있는 것을 DOM과 터치 화면으로 확인했습니다. **코드는 수정하지 않았으며 연결 담당에게 수정 제안만 전달합니다.**

## 배치 기준

- PC: 왼쪽 비교 목록 + 오른쪽 선택한 프로그램 상세. 화면 밖으로 페이지를 늘리지 않고 각각의 표·상세 내부에서만 스크롤.
- 태블릿: 가로에서는 두 칸, 좁은 세로에서는 목록/상세 전환. 1024×768과 768×1024에서 시안을 확인.
- 모바일: 필수 탭 항상 노출, 작은 썸네일을 둔 5개 목록. 항목을 눌러 상세로, 목록으로 돌아가면 선택·목록 위치 유지. 목록 위에 큰 사진을 고정하지 않음.
- 공통: 12px 보조 / 14px 본문 / 18px 제목 중심의 글자 체계. 능력·비용·정원은 같은 열과 동일 단위로 조판. 팀 색은 선택 강조에만 제한.
- 사진: 960판은 큰 상세, 480판은 썸네일·모바일. 같은 16:9 비율, `object-fit:cover`, 중심점 50%/50%. 문구는 이미지에 합성하지 않음.

시안은 실제 게임의 수정 화면이 아닙니다. `preview.html`에만 상호작용을 넣었습니다. 현재 게임에 존재하는 OVS 5종을 기준으로 하며, 개인별 신청 자격·기간·부상/성장 확률·제휴 정원은 연결 시 실제 계산을 읽어야 합니다.

## 실제 플레이 범위

main `8b4b902`의 index.html과 전체 로컬 에셋을 그대로 실행했습니다. PC 1440×900, 터치 모바일 390×844, 터치 태블릿 1024×768의 Chromium 환경입니다. 배포 사이트와 실물 Safari/iPadOS 검수는 아닙니다.

새 서울 하운즈 단장으로 취임 → 의료 설정 확인 → 김승호 감독 2년 선임 → 외국인 후보 관찰과 호세 산체스 협상·계약 → 캠프·시범경기 → 3월 28일 개막전 결과(1:1) → 3월 29일 3D 중계 진입·일시정지·나가기까지 확인했습니다. 여러 결정은 진행 전 확인에서 기본안 진행을 선택했습니다. 시즌 전체의 난이도나 AI 구단 운영을 평가한 작업은 아닙니다.

초기 PC 게임 페이지의 예외·응답 관찰기에서는 페이지 예외와 로컬 리소스 누락 응답이 관찰되지 않았습니다. 모바일·태블릿은 실제 조작과 화면 검토 중심이며 모든 보조 페이지의 네트워크·예외를 전수 수집한 검사는 아닙니다. 이것을 게임 전체의 무오류 보장으로 해석하지 않습니다. 모바일 ‘자세히’는 한 메시지를 펼치고 실제 touchStart/move/end로 스크롤했을 때 열린 상태와 본문이 유지됐습니다. 간헐적 문제가 모든 기기에서 해결됐다는 결론은 내리지 않았습니다.
