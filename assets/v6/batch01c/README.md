# v6c 선수 시범 · B안 직접 유니폼 생성

**리뷰 전용 · ArcFace0.40 미통과 · main 반영 금지.**

요청서 `docs/asset-requests/2026-11-05-codex-v6c-player-faces.md`의 B안을 시범 제작했습니다. 가상 한국인 성인 선수20명(18~35세)×코메츠·하운즈·블레이즈3구단, 총60장입니다. 머리·목·어깨·상의가 자연스럽게 이어진 사진이며 공통 몸통에 얼굴을 붙이지 않았습니다. 코메츠 원본을 기준으로 같은 인물의 의상을 이미지 생성 도구에서 변경했습니다. A안 합성 개선까지 동시에 납품한 것은 아닙니다.

## 품질과 한계

- 모자를 생성 단계에서 깊게 썼고 챙이 눈썹 가까이 옵니다. 모자 늘리기·얼굴/몸통 붙이기는0회입니다.
- 원본 시트의 머리 위 여백은 부족한 셀이 있어, 각 인물의3구단 사진에 동일한 전체 사진 이동을 적용하고 비어 있는 상단의 스튜디오 배경만 연장했습니다. 모자/피부/옷의 부분 변형은 없습니다.512 기준 모자 실루엣 여백 추정 최저56px이며 `framing_validation.json`에 방법과 이동값이 있습니다.
- 옷감 직조·칼라·단추·자수·챙 봉제와 모자 음영이 사진에 함께 생성되어 키 색 UV 오버레이보다 자연스럽게 읽힙니다.256px 비교판4장에20명 전원의3구단 버전을 나란히 넣었습니다.
- 가슴 글씨가 단추 줄에서 인위적으로 끊기는 현상은 검토판에서 보이지 않았지만, 일부 글씨 꼬리는 가슴 사진 하단 크롭에 닿습니다. 하운즈 심벌은 생성 묶음별로 모양이 달라 정확한 원본 도형 고정은 미완료입니다.
- 같은 인물의3구단 조합60쌍 코사인 최저 **0.848919**입니다.0.60은 이번 시범의 내부 일관성 검사선이며 요청한 중복 기준0.40과 다른 용도입니다. 동일인 유지 검사 통과가 서로 다른 인물의 중복 검사 통과를 뜻하지 않습니다.

## 얼굴 중복 검수

최종256 WebP 시트를 실제 디코딩해 v6과 같은 ArcFace 모델·5점 정렬·L2 정규화·원래 코사인으로 비교했습니다. **0.40을 올리거나 점수를 재척도화하지 않았습니다.**

- 다른 인물의 구단별 사진 전체1,710쌍: 최대 **0.754399**,0.40 이상 **827쌍**, 쌍 단위 통과율 **51.64%**.
- 현재 main v6b100명과6,000쌍: 최대 **0.566061**,0.40 이상 **364쌍**.
- 비교용 기존 v6b 자체4,950쌍: 초과1471쌍, 쌍 단위 통과율70.28%. 인원·연령 구성이 달라 통제 실험은 아니며, **이번 시범의 다양성 통과율 개선을 주장하지 않습니다.**

`validation.json`에 모든 초과 쌍·최근접 상대·모델 SHA·입력 출처, `validation_embeddings.npz`에 실제60개+v6b100개 임베딩을 기록했습니다. 인물별 최근접은 manifest에도 있습니다. 특정 실존 인물로 식별되는 재현은 육안 검수에서 찾지 못했으나 모든 실존 인물과의 전수 비교는 아닙니다. 실패 결과이므로 [assets/v6c-batch01c-review](https://github.com/kkhkkh20-bit/front-office/tree/assets/v6c-batch01c-review/assets/v6/batch01c)에 보관하고 main으로 넣지 않습니다.

## 파일과 사용

| 파일 | 규격 / 용도 |
|---|---|
| `sheets/128/{team}.webp` | RGB720×576,5열×4행,셀 둘레8px 여백,20명 |
| `sheets/256/{team}.webp` | RGB1360×1088,5열×4행,셀 둘레8px 여백,20명 |
| `manifest.json` | identity→team→해상도별 시트/셀, 구단별 의상 버전, 최근접/나이/출처 |
| `archive/{team}.zip` | 구단마다512 보관본20개+128/256낱장40개+생성 원본 시트5개 |
| `previews/large_cards_01..04.png` | 256px 크기로20명×3구단 전원 비교 |
| `previews/v6b_vs_v6c_256.png` | 실제 게임의 기존256px 결과와 새 B안 비교. **서로 다른 사람이며 동일인 전후 사진이 아님** |
| `previews/cap_collar_details.png` | 모자·얼굴·칼라 경계10명×3구단 확대 |
| `ASSET_PREVIEW.png` |20명 원본 전체 |

원본 시트는1254×1254,1인625×625 유효 셀을512로 축소했습니다.128/256판은 최종 WebP를 검수했고 알파·의상 정렬 시트는 없습니다. **RGB 완성 사진을 그대로 표시하고 v6b UV 유니폼 합성·모자 색 교체·아래로 늘리기·심벌 재부착을 적용하지 않습니다.** 게임 연결·코드는 Claude 담당이며 이번 작업에서 수정하지 않았습니다.

런타임 이미지6장 합계 **746,440bytes**,128판3장 193,676bytes /256판3장 552,764bytes입니다.100명×10구단1,000장으로 단순 비례하면128 약3.08MiB /256 약8.79MiB로, 실제 시트 압축에 따라 달라집니다. `production_plan.json`에 일관성·용량·검수·구단별 캐시 계획을 적었습니다. **1,000장 대량 제작과 원정 유니폼 제작은 하지 않았습니다.** 다양성과 심벌 고정 문제를 해결하기 전 대량 제작을 권하지 않습니다.

최종 독립 형식 검증16개 항목을 통과했습니다. 최종 시트에서 재계산한 임베딩·전체 비교 수·ZIP CRC·파일 해시·셀 좌표·원본 대응을 확인했습니다. 인접 사진의 WebP 색 번짐을 막기 위해 셀 둘레8px을 확보했습니다(128판 pitch144 /256판 pitch272). 실제 납품256판에서 붉은 모자40장의 상단 여백을 재측정한 최솟값은512 환산54px입니다. 남색 모자는 실루엣 추정과 전원 육안 검토를 함께 사용했습니다.
